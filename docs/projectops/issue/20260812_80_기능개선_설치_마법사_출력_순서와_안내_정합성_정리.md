### 어떤 문제를 해결하고 싶으신가요?

Spring 프로젝트에 v0.2.0을 대화형으로 설치하면서 관찰한 UX 문제를 한 곳에 모읍니다. 개별 버그(#77)나 큰 흐름 변경(#78)과 달리, 아래 항목들은 **"설치는 됐는데 사용자가 상황을 정확히 알 수 없게 만드는"** 안내 정합성 문제입니다.

---

**1. 묻지도 않은 라이브러리 배포 워크플로우가 설치됩니다**

Nexus 라이브러리 publish 워크플로우는 "라이브러리 프로젝트에만 필요합니다" 라는 설명과 함께 포함 여부를 물어봅니다. 여기서 `아니오` 를 골랐는데도, 완료 화면을 보면 `PROJECT-SPRING-GITHUB-PACKAGES-PUBLISH.yml` 이 설치돼 있습니다.

이 워크플로우도 성격상 **라이브러리를 패키지 저장소에 배포하는 용도**입니다. Nexus 것만 `payload/workflows/spring/nexus/` 하위에 있어 opt-in 질문 대상이 되고, GitHub Packages 것은 `payload/workflows/spring/` 바로 아래에 있어 무조건 설치되는 구조입니다. 같은 성격인데 하나만 묻습니다.

사용자 입장에서는 방금 "라이브러리 배포는 필요 없다"고 답했는데 라이브러리 배포 워크플로우가 깔린 셈이라, 질문의 의미가 무너집니다.

**2. 배포 워크플로우 4종이 한꺼번에 설치되는데, 실제로 쓸 것은 보통 하나입니다**

Spring 설치 시 무중단 배포(Nginx), 무중단 배포(Traefik), PR 프리뷰, 단일 서버 배포가 **전부** 설치됩니다. 이 넷은 서로 대체재입니다. Nginx와 Traefik을 동시에 쓰는 경우는 없습니다.

부작용이 두 가지입니다.

- `.github/workflows/` 에 쓰지 않을 워크플로우가 쌓입니다. 이후 업데이트마다 이 파일들의 충돌 여부를 계속 검사하게 됩니다.
- **환경설정 질문이 불어납니다.** 7개 항목 중 도메인은 Nginx/Traefik 전용, 마운트 경로는 Traefik/단일 서버 전용, 포트는 단일 서버 전용입니다. 안 쓸 워크플로우 때문에 답해야 하는 질문이 생깁니다.

각 질문 옆에 `[spring 무중단배포(Nginx)·무중단배포(Traefik)·PR 프리뷰·단일 서버 배포]` 처럼 용처를 병기해 준 것은 좋은 설계입니다. 다만 그 라벨이 길어진 이유 자체가 "전부 설치" 이기도 합니다. 배포 방식을 하나 고르게 하면 질문 수와 설치 파일 수가 같이 줄어듭니다.

**3. 완료 화면이 정작 필요한 Secret 을 알려주지 않습니다**

완료 후 안내는 두 가지입니다: `WORKFLOW_PAT`(선택), Actions 권한 확인. 그런데 방금 설치한 Spring 배포 워크플로우들이 실제로 요구하는 Secret 은 이것들입니다.

`SERVER_HOST`, `SERVER_USER`, `SERVER_PASSWORD`, `SSH_KEY`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`, `DOCKER_USERNAME`, `DOCKER_PASSWORD`, `APPLICATION_PROD_YML`, `FIREBASE_KEY_JSON`, `VERTEX_SA_KEY`

**하나도 안내되지 않습니다.** 설치는 성공했다고 나오지만 이 상태로는 배포가 돌지 않습니다. 사용자는 워크플로우 YAML을 직접 열어 `secrets.` 문자열을 찾아내야 합니다. 완료 화면의 마지막 안내가 "이제 뭘 하면 되는지" 를 알려주는 자리인데, 정작 제일 중요한 항목이 빠져 있습니다.

설치된 워크플로우에서 참조하는 Secret 이름을 모아 필수/선택으로 나눠 보여주면 됩니다. SSH 인증 방식을 `password` 로 답했으면 `SSH_KEY` 는 빼는 식으로, 사용자가 이미 답한 값에 맞춰 좁힐 수도 있습니다.

**4. 경고 메시지가 감지 박스 바깥으로 새어나옵니다**

```
◇  무엇을 설치할까요?
│  설치 / 업데이트 — ...
⚠️  버전을 자동 감지하지 못해 기본값 0.0.1을 사용합니다 — ...
┌  🔍 프로젝트를 살펴보는 중...
│  ✓ build.gradle 발견 → spring 감지
│  ✓ 버전: v0.0.1 · 브랜치: main
```

버전 감지 경고가 **"프로젝트를 살펴보는 중" 박스가 열리기 전에** 출력됩니다. 감지 과정에서 나온 경고인데 감지 박스 밖에, 그것도 위에 찍히니 앞의 모드 선택에 대한 경고처럼 보입니다.

감지 함수를 먼저 호출하고 그 결과로 박스를 그리기 때문에 생기는 순서 문제입니다. 감지 중 발생한 경고는 모아뒀다가 해당 박스 안, 관련 줄 바로 아래에 출력해야 맥락이 맞습니다.

**5. 대화형 사용자에게 CLI 플래그로 해결하라고 안내합니다**

같은 경고의 문구가 `--project-version으로 직접 지정하거나 version.yml을 확인하세요` 입니다. 지금 사용자는 `npx project-auto-wizard` 를 인자 없이 실행해 대화형 마법사 안에 있습니다. 여기서 CLI 플래그를 알려주면 "그럼 지금 나가서 다시 실행하라는 건가" 가 됩니다.

대화형에서는 뒤에 나오는 `수정하기 > 버전` 에서 바로 고칠 수 있다고 안내하는 편이 맞습니다. 같은 경고라도 대화형과 비대화형에서 안내가 달라야 합니다.

**6. 완료 요약에 "내가 답한 값" 이 없습니다**

완료 화면은 설치된 파일 목록은 보여주지만, 방금 답한 환경설정 7개 항목의 최종 값은 보여주지 않습니다. 마지막으로 눈으로 검산할 기회가 사라집니다. 오타를 냈어도 그 자리에서는 알 수 없고, 나중에 배포가 실패한 뒤에야 발견합니다.

**7. (재현 확인 필요) 긴 값 입력 시 프롬프트 줄이 겹쳐 보입니다**

도메인 입력 중 프롬프트 줄이 두 번 출력된 것처럼 보이는 현상이 있었습니다.

```
◆  ↳ 값 입력 (Enter=기본값 «example.com» 유지): api.palim.suhsaechan.
◆  ↳ 값 입력 (Enter=기본값 «example.com» 유지): api.palim.suhsaechan.kr
```

텍스트 입력 엔진이 키 입력마다 `\r` + 현재 줄 지우기로 한 줄을 다시 그리는 방식이라, 프롬프트와 입력값 길이의 합이 터미널 폭을 넘어 줄바꿈되면 커서가 논리적 줄 시작이 아니라 감긴 줄의 시작으로 돌아가 잔상이 남을 수 있습니다. 다만 이번 로그만으로 단정하기 어려워, 좁은 터미널 폭에서 긴 값을 넣어 재현 여부부터 확인이 필요합니다.

### 제안하는 해결 방법

우선순위를 나눠 제안합니다.

**먼저 고칠 것 (설치 결과가 실제로 잘못되거나 못 쓰게 되는 것)**

- **3번, Secret 안내**: 설치된 워크플로우에서 참조하는 Secret 이름을 모아 완료 화면에 필수/선택으로 나눠 출력합니다. 지금은 설치 직후 상태에서 배포가 동작하지 않는데 그 사실이 안내되지 않습니다.
- **1번, GitHub Packages publish**: Nexus 와 같은 성격이므로 같은 opt-in 질문 대상으로 옮기거나, 최소한 "라이브러리 배포 워크플로우" 를 한 묶음으로 묻습니다. 물어놓고 다른 걸 깔면 안 됩니다.

**다음으로 고칠 것 (안내 정합성)**

- **4번, 경고 출력 순서**: 감지 중 경고를 모아뒀다가 감지 박스 안에서 출력합니다.
- **5번, 경고 문구 분기**: 대화형에서는 마법사 안에서 고치는 방법을, 비대화형에서는 CLI 플래그를 안내합니다.
- **6번, 완료 요약에 답변 값 표시**: 환경설정 최종 값을 완료 화면에 함께 보여줍니다. (#79 설치 로그와 같은 데이터를 쓰므로 함께 구현하면 이득입니다)

**설계 논의가 필요한 것**

- **2번, 배포 워크플로우 선택**: 4종 중 하나를 고르게 하면 파일 수와 질문 수가 같이 줄지만, 나중에 다른 방식으로 바꾸려면 재설치가 필요해집니다. "전부 깔고 안 쓰는 건 방치" 와 "하나만 깔고 나중에 추가" 중 어느 쪽이 나은지 판단이 필요합니다. 개인적으로는 배포 방식을 묻되 나머지도 참고용으로 남기는 절충(예: 선택하지 않은 것은 비활성 상태로 설치)을 검토할 만하다고 봅니다.
- **7번**: 재현 조건부터 확인한 뒤 별도 이슈로 분리할지 결정합니다.

### 고려한 다른 방법(선택)

- **항목별로 이슈를 쪼개기** — 추적은 정확해지지만 7건이 서로 같은 화면(감지 로그, 환경설정 질문, 완료 요약)을 건드려 중복 작업과 충돌이 생깁니다. 한 이슈로 묶어 화면 단위로 정리하는 편이 낫다고 판단했습니다. 2번과 7번은 판단이 갈리므로 논의 후 분리할 수 있습니다.
- **문서(README)로만 보완** — Secret 목록을 문서에 적어두는 방법도 있지만, 설치 직후 바로 필요한 정보는 그 자리에서 보여줘야 합니다. 설치는 끝났다고 하는데 문서를 찾아 읽으라는 것은 완료 화면의 역할 포기입니다.
