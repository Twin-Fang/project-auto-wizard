### 무슨 일이 있었나요?

**일부 워크플로우 템플릿에 `@wizard` 마커가 하나도 없어서, 예시용 기본값이 그대로 설치됩니다.** 마법사가 묻지도 않고 고치지도 않으므로 사용자는 그 값이 자기 프로젝트와 무관하다는 사실조차 모릅니다.

payload 워크플로우 전체의 `@wizard` 마커 개수를 세어보면 이렇습니다.

| 템플릿 | 마커 | 상태 |
|---|---|---|
| `spring/server-deploy/PROJECT-SPRING-SIMPLE-CICD.yaml` | 8 | 정상 |
| `spring/server-deploy/PROJECT-SPRING-NONSTOP-TRAEFIK-CICD.yaml` | 7 | 일부 누락 |
| `spring/server-deploy/PROJECT-SPRING-NONSTOP-NGINX-CICD.yaml` | 6 | 일부 누락 |
| `spring/server-deploy/PROJECT-SPRING-PR-PREVIEW.yaml` | 4 | 정상 |
| `common/secret-backup/PROJECT-COMMON-SECRET-FILE-UPLOAD.yaml` | **0** | 전부 하드코딩 |
| `spring/PROJECT-SPRING-GITHUB-PACKAGES-PUBLISH.yml` | **0** | 전부 하드코딩 |
| `spring/nexus/*` (2개) | **0** | 전부 하드코딩 |

---

**① Secret 서버 백업 (마커 0개)**

설치 시 "포함할까요?" 라고 물어보고 `예` 를 고르면 이 상태로 깔립니다.

```
PROJECT_NAME: "my-project"
ROLE: "backend"
SERVER_BASE_PATH: "/volume1/projects"
SSH_PORT: "2022"
```

`my-project` 는 어느 프로젝트에도 맞지 않는 예시값입니다. 그런데 이 워크플로우는 **개발 브랜치에 push 할 때마다 실행**됩니다. 결과적으로 서버 경로가 `/volume1/projects/my-project/github_secret/backend` 로 잡히고, Secret 이 설정돼 있지 않은 초기 상태에서는 push 마다 실패 알림이 쌓입니다.

`PROJECT_NAME` 은 다른 템플릿에서 이미 `@wizard ask:@repo` 로 레포명을 자동 채우고 있습니다. 같은 값인데 이 템플릿에서만 예시값이 남습니다.

**② GitHub Packages publish (마커 0개)**

```
java-version: '17'
```

트리거는 main push 와 `v*.*.*` 태그입니다. 즉 **릴리스할 때마다 자동으로 실행**됩니다. JDK 는 17 고정이라, 프로젝트가 21이든 25든 무시하고 17로 빌드를 시도해 실패합니다.

라이브러리가 아닌 일반 서비스 프로젝트에는 애초에 필요 없는 워크플로우인데 선택지 없이 설치된다는 문제(#80 의 1번 항목)와 겹칩니다. 설치 여부를 묻게 되더라도, 설치를 택한 사람에게는 JDK 버전이 맞아야 합니다.

**③ Nginx 무중단 배포 (마커 6개, 핵심 값이 빠짐)**

무중단 배포의 동작을 좌우하는 값들에 마커가 없습니다.

```
BLUE_PORT: "8080"
GREEN_PORT: "8081"
NGINX_RP_CONF: "/etc/nginx/sites-enabled/example.conf"
NGINX_BACKUP_DIR: "/volume1/project/nginx/backups"
SSH_PORT: "2022"
```

이 워크플로우는 `NGINX_RP_CONF` 파일을 열어 `proxy_pass` 포트를 blue/green 으로 토글하는 방식으로 무중단을 구현합니다. **경로가 틀리면 무중단 전환 자체가 동작하지 않습니다.** 그런데 `example.conf` 라는 명백한 예시값이 들어 있고 마법사는 묻지 않습니다.

`NGINX_BACKUP_DIR` 의 `/volume1/project/` 는 오타로 보입니다. 같은 파일의 `VOLUME_HOST_PATH` 는 `/volume1/projects/` (복수형)입니다.

또한 마법사가 이미 물어보는 "외부 노출 포트" 는 SIMPLE 배포용이고, Nginx 무중단은 blue/green 두 포트를 씁니다. 무중단을 고른 사용자는 물어보지도 않은 8080/8081 을 쓰게 됩니다.

**④ JAVA_VERSION 기본값이 프로젝트와 무관하게 고정**

마커가 있는 템플릿들도 기본값이 `@wizard ask:21` 로 고정입니다. 프로젝트의 `build.gradle(.kts)` 에는 `JavaLanguageVersion.of(25)` 처럼 실제 툴체인 버전이 적혀 있는데 이걸 읽지 않습니다. 사용자가 질문에서 그대로 Enter 를 누르면(안내 문구가 "Spring은 보통 21" 이라 그럴 가능성이 높습니다) 러너 JDK 와 프로젝트 툴체인이 어긋나 빌드가 실패합니다.

빌드 번호는 이미 프로젝트 파일에서 읽고 있습니다(`detectBuildNumber`). JDK 버전도 같은 방식으로 읽어 기본값으로 제시하는 것이 일관됩니다.

### 기대했던 동작

- 설치되는 워크플로우에 예시값(`my-project`, `example.conf`, `example.com`)이 그대로 남으면 안 됩니다. 마법사가 채우거나, 최소한 "이 값은 직접 고쳐야 한다"고 알려야 합니다.
- 워크플로우 동작을 좌우하는 값(nginx 설정 경로, blue/green 포트)은 물어봐야 합니다.
- `JAVA_VERSION` 기본값은 프로젝트의 `build.gradle(.kts)` / `pom.xml` 툴체인 설정에서 읽어 제시해야 합니다.
- `NGINX_BACKUP_DIR` 의 `/volume1/project/` 오타를 `/volume1/projects/` 로 바로잡아야 합니다.
- 마커가 0개인 템플릿은 "치환할 게 없는 템플릿" 인지 "마커를 빠뜨린 템플릿" 인지 구분되어야 합니다. 후자를 자동으로 잡아낼 검사가 있으면 같은 실수가 반복되지 않습니다.
