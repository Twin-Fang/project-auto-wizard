[예제 레포](https://github.com/Twin-Fang/project-auto-wizard-example)는 릴리스 자동화가 이미 설치된 작은 Node 프로젝트입니다. GitHub를 떠나지 않고 project-auto-wizard의 두 부분을 모두 체험할 수 있습니다. 모든 것을 설치해 주는 **설치 마법사**, 그리고 그것이 자동화하는 **릴리스**입니다. 릴리스에서는 커밋 종류가 다음 버전을 정하고, 릴리스 PR에 노트가 달린 뒤 저절로 머지되고, 태그와 GitHub Release, CHANGELOG가 생깁니다.

내 컴퓨터에 설치할 것도, Secret도 필요 없습니다. 둘 중 하나를 고르세요.

| | Codespace에서 (안내형) | 클릭만으로 |
|---|---|---|
| 하는 일 | 브라우저 속 터미널에 명령 두 개 입력 | GitHub 웹 화면에서 클릭 |
| 보는 것 | 진짜 설치 마법사, 그다음 실제 릴리스 | 실제 릴리스 |
| 진행 중 설명 | 있음 (영어 또는 한국어) | 이 페이지의 단계를 따라감 |
| 시간 | 약 2분 + 5분 | 약 5분 |

## Codespace에서 (안내형)

[Codespace](https://docs.github.com/ko/codespaces)는 GitHub에서 돌아가는 VS Code와 리눅스 터미널을 브라우저로 여는 기능입니다. 예제 레포가 Node.js, git, `gh` 명령을 미리 준비해 둡니다.

<img src="https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-codespaces.gif" alt="예제 레포를 GitHub Codespaces로 열어 설치 마법사를 실행하고, 복사본에서 v0.4.0을 릴리스하는 과정" width="880" />

같은 과정을 한국어 자막 영상으로 볼 수 있습니다: [MP4](https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-codespaces.ko.mp4).

### 1부: 설치 마법사 실행

<Steps>

1. **Codespace 열기.** [예제 레포](https://github.com/Twin-Fang/project-auto-wizard-example)에서 **Open in GitHub Codespaces**를 누르고 **Create new codespace**를 누릅니다. 처음에는 1분 정도 걸립니다.

   ✓ 브라우저에 VS Code가 열리고 `TRY-IT.md`가 보입니다.

2. **터미널 켜기.** VS Code가 이 폴더 파일의 작성자를 신뢰하는지 물으면 **폴더 신뢰 및 계속**(Trust folder and continue)을 누릅니다. 터미널이 안 보이면 **Ctrl + `**로 엽니다.

   ✓ 터미널에 `npm run try:install`과 `npm run try:release`가 안내됩니다.

3. **설치 마법사 실행.** `npm run try:install`을 입력하고 **Enter**를 누릅니다. 언어와 샘플 프로젝트(Node, Spring, Python)를 고른 뒤, 마법사의 질문마다 **Enter**를 눌러 기본값으로 진행합니다.

   ✓ 설치된 파일 목록이 `version.yml`, `README.md`로 끝납니다. `.github/workflows/` 아래 릴리스 워크플로우와 `.github/scripts/` 아래 스크립트입니다. 임시 폴더에서 일어나는 일이라 아무것도 push하지 않습니다.

</Steps>

### 2부: 실제 릴리스 만들기

릴리스는 내 레포의 GitHub Actions에서 일어나므로, 이 부분은 템플릿을 복사한 내 레포에서 합니다.

<Steps>

1. **템플릿 복사.** [템플릿으로 레포 만들기](https://github.com/new?template_name=project-auto-wizard-example&template_owner=Twin-Fang)를 엽니다. 내 계정, 아무 이름, **Public**을 고르고 **Include all branches**는 끈 채로 **Create repository**를 누릅니다.

2. **복사본에서 Codespace 열기.** 새 레포에서 **Code** > **Codespaces** > **Create codespace on main**을 누릅니다. 1부처럼 폴더를 신뢰합니다.

3. **릴리스 실행.** `npm run try:release`를 입력하고 **Enter**를 누릅니다. 단계마다 무엇을 하는지 설명하며 진행합니다.

   - 이 Codespace가 내 복사본에 속해 있는지 확인합니다.
   - `main`에서 `develop`을 만듭니다.
   - `feat:`, `fix:`, `feat!:` 각각이 어떤 버전이 되는지 보여 주고 고르게 합니다.
   - `src/greet.js`를 고쳐 커밋, push하고 `develop` > `main` 릴리스 PR을 엽니다.
   - GitHub Actions가 버전을 확정하고, 릴리스 노트와 CHANGELOG를 쓰고, 머지하고, 태그와 Release를 발행하기를 기다립니다.

   ✓ 마지막에 `vX.Y.Z 릴리스 완료`와 함께 Release, `CHANGELOG.md`, README 버전 줄 링크가 나옵니다.

4. **비교해 보기.** `npm run try:release`를 다시 실행해 다른 종류를 고르세요. `fix:`는 patch 버전을, `feat!:`는 major 버전을 올립니다.

</Steps>

<Aside>
**비용.** Codespace는 내 GitHub 계정의 월 무료 사용량에서 빠집니다(GitHub Free 기준 월 120 core-hours, 기본 2코어 머신으로 약 60시간). 계정에 결제 수단이 없으면 한도에서 멈추고 요금은 청구되지 않습니다. 다 쓴 뒤에는 [github.com/codespaces](https://github.com/codespaces)에서 **...** > **Delete**로 지웁니다.
</Aside>

## 클릭만으로

같은 릴리스를 GitHub 웹 화면에서 손으로 해 봅니다.

<img src="https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-it.gif" alt="예제 레포를 복사해 GitHub 웹 화면에서 v0.3.0을 릴리스하는 과정" width="880" />

같은 과정을 한국어 자막 영상으로 볼 수 있습니다: [MP4](https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-it.ko.mp4).

<Aside>
먼저 보기만 하고 싶다면 예제 레포의 [PR](https://github.com/Twin-Fang/project-auto-wizard-example/pulls?q=is%3Apr), [Actions 실행 기록](https://github.com/Twin-Fang/project-auto-wizard-example/actions), [Releases](https://github.com/Twin-Fang/project-auto-wizard-example/releases)에서 이미 돈 릴리스를 확인할 수 있습니다.
</Aside>

<Steps>

1. **템플릿 복사.** [예제 레포](https://github.com/Twin-Fang/project-auto-wizard-example)에서 **Use this template** > **Create a new repository**를 누릅니다. 소유자는 자기 계정, 이름은 자유, **Public**을 고릅니다. **Include all branches**는 끈 채로 **Create repository**를 누릅니다.

   ✓ 새 레포에 `.github/workflows/`, `version.yml`, 마지막이 `Latest Version : v0.x.y`인 README가 있습니다. 아직 릴리스는 생기지 않습니다.

2. **개발 브랜치 만들기.** 브랜치 메뉴(`main`이라고 표시됨)를 열고 `develop`을 입력한 뒤 **Create branch develop from main**을 고릅니다.

   ✓ 브랜치 메뉴에 `develop`과 `main`이 보입니다.

3. **`develop`에 기능 커밋.** `develop`에서 `src/greet.js`를 열고 연필 아이콘을 눌러 무언가를 바꿉니다(예: `GREETINGS`에 `es: "Hola"` 추가). **Commit changes**를 눌러 메시지를 `feat: greet in Spanish`로 쓰고, **Commit directly to the develop branch**를 그대로 둔 채 커밋합니다.

   ✓ `develop`이 `main`보다 커밋 하나 앞서 있고, 그 커밋 메시지가 `feat:`로 시작합니다.

4. **릴리스 PR 열기.** **Pull requests** > **New pull request**에서 base를 `main`, compare를 `develop`으로 두고 **Create pull request**를 누릅니다.

5. **릴리스되는 과정 보기.** 1분 정도 지나면 PR에서 `PROJECT-AUTO-CHANGELOG-CONTROL`이 실행됩니다. 다음 버전을 확정하고, 릴리스 노트를 댓글로 달고, `CHANGELOG.md`를 갱신한 뒤 PR을 머지합니다. `feat:` 커밋은 minor 버전을 올립니다.

   ✓ PR이 `github-actions[bot]`에 의해 **Merged** 상태가 되고, `[0.3.0] ✨ Features` 같은 댓글이 달립니다.

6. **릴리스 확인.** **Releases**에 노트가 담긴 새 `vX.Y.Z` 릴리스가 있습니다. `CHANGELOG.md`에 항목이 생기고 README 버전 줄도 새 버전을 표시합니다.

</Steps>

<Aside type="caution">
**커밋 직전에 메시지를 확인하세요.** GitHub가 Copilot 제안으로 메시지를 바꿔 넣을 수 있습니다. 버전은 접두사로 정해지므로 `feat:`가 없으면 patch 릴리스가 됩니다.

**`develop`은 지우지 마세요.** 머지 후 GitHub가 `develop` 브랜치 삭제를 권하는데, 그대로 두어야 다음 릴리스 PR을 열 수 있습니다.
</Aside>

## 더 해 보기

- `develop`에 `fix:` 커밋을 하고 릴리스 PR을 다시 열면 patch 버전만 올라갑니다.
- `feat!: rename greet`처럼 `!`를 붙이면 major 버전이 올라갑니다.
- `develop`의 `version.yml`에서 `release_automerge: false`로 바꾸면 릴리스 PR 제목이 `chore(release): vX.Y.Z`로 바뀌고, 어떤 머지 방식이든 직접 머지하기를 기다립니다.
- 각 워크플로우가 하는 일은 [릴리스 흐름](../../understand/release-flow/), 자기 프로젝트에 설치하는 방법은 [빠른 시작](../quickstart/)을 보세요.

## 무언가 일어나지 않을 때

- **Codespace 터미널이 비어 있음**: VS Code가 제한 모드입니다. 상태 표시줄의 **제한 모드**(또는 위쪽 배너)를 눌러 폴더를 신뢰하세요.
- **`npm run try:release`가 "아직 내 레포가 없습니다"라고 함**: 템플릿의 **Open in GitHub Codespaces** 버튼으로 연 Codespace입니다. 템플릿을 먼저 복사하고(2부 1단계) 복사본에서 Codespace를 여세요.
- **`npm run try:release`가 "예상 시간 안에 끝나지 않았습니다"에서 멈춤**: 복사본의 **Actions** 탭을 여세요. 대기 중인 실행은 조금 뒤 끝나고, 실패한 실행은 마지막 줄에 무엇이 막았는지 나옵니다.
- **PR에서 워크플로우가 돌지 않음**: PR이 `develop`에서 `main`으로 가는지, 레포의 **Actions** 탭이 켜져 있는지 확인하세요.
- **PR을 만들 수 없음("entirely different commit histories")**: **Include all branches**를 켜고 복사한 경우입니다. `develop`을 지우고 `main`에서 다시 만드세요(2단계).
- **PR이 자동으로 머지되지 않음**: **Actions** 탭에서 실행을 열면 마지막 줄에 머지를 막은 원인(예: 브랜치 보호 규칙)과 바꿀 곳이 나옵니다.
- **CHANGELOG에 이전 버전도 있음**: 예제 레포의 릴리스 기록이 복사본에 그대로 따라온 것입니다.
