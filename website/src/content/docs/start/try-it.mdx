The [example repository](https://github.com/Twin-Fang/project-auto-wizard-example) is a small Node project with the release automation already installed. You can try both halves of project-auto-wizard without leaving GitHub: the **installer** that sets everything up, and the **release** it automates (the commit type decides the next version, the release PR gets its notes and merges itself, and a tag, a GitHub Release and the CHANGELOG appear).

Nothing is installed on your computer and no secrets are needed. Pick one way:

| | In a Codespace (guided) | Clicks only |
|---|---|---|
| What you do | Type two commands in a terminal in your browser | Click through GitHub's web UI |
| What you see | The real installer, then a real release | A real release |
| Explained as it runs | Yes, in English or Korean | Follow the steps on this page |
| Time | about 2 + 5 minutes | about 5 minutes |

## In a Codespace (guided)

A [Codespace](https://docs.github.com/codespaces) is VS Code with a Linux terminal, running on GitHub and opened in your browser. The example repository sets it up with Node.js, git and the `gh` command.

<img src="https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-codespaces.gif" alt="Opening the example repository in GitHub Codespaces, running the installer, then releasing v0.4.0 from a copy" width="880" />

The same recording as a video: [MP4](https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-codespaces.mp4).

### Part 1: run the installer

<Steps>

1. **Open the Codespace.** On the [example repository](https://github.com/Twin-Fang/project-auto-wizard-example), click **Open in GitHub Codespaces**, then **Create new codespace**. It takes about a minute the first time.

   ✓ VS Code opens in the browser with `TRY-IT.md`.

2. **Turn on the terminal.** If VS Code asks whether you trust the authors of the files in this folder, click **Trust folder and continue**. Then open the terminal with **Ctrl + `** if it is not open.

   ✓ The terminal shows `npm run try:install` and `npm run try:release`.

3. **Run the installer.** Type `npm run try:install` and press **Enter**. Choose a language and a sample project (Node, Spring or Python). Then press **Enter** at each question of the wizard to keep the defaults.

   ✓ The list of installed files ends with `version.yml` and `README.md`: release workflows under `.github/workflows/` and their scripts under `.github/scripts/`. This happens in a temporary folder; nothing is pushed.

</Steps>

### Part 2: cut a real release

The release runs in GitHub Actions of a repository you own, so this part uses your copy of the template.

<Steps>

1. **Copy the template.** Open [Create a repository from the template](https://github.com/new?template_name=project-auto-wizard-example&template_owner=Twin-Fang). Choose your account, any name and **Public**. Leave **Include all branches** off, then click **Create repository**.

2. **Open a Codespace on your copy.** In your new repository click **Code** > **Codespaces** > **Create codespace on main**. Trust the folder as in Part 1.

3. **Run the release.** Type `npm run try:release` and press **Enter**. It explains each step as it goes:

   - checks that the Codespace belongs to your copy,
   - creates `develop` from `main`,
   - shows the version that `feat:`, `fix:` and `feat!:` would lead to, and lets you choose,
   - edits `src/greet.js`, commits, pushes and opens the `develop` > `main` release PR,
   - waits while GitHub Actions confirms the version, writes the release notes and CHANGELOG, merges, and publishes the tag and the Release.

   ✓ It ends with `Released vX.Y.Z` and links to the Release, `CHANGELOG.md` and the README version line.

4. **Compare.** Run `npm run try:release` again and choose another kind of change: `fix:` raises the patch version, `feat!:` the major version.

</Steps>

<Aside>
**Cost.** A Codespace uses the free monthly quota of your own GitHub account (GitHub Free: 120 core-hours a month, about 60 hours on the default 2-core machine). Without a payment method on your account it stops at the quota and never bills you. When you are done, delete it at [github.com/codespaces](https://github.com/codespaces): **...** > **Delete**.
</Aside>

## Clicks only

The same release, done by hand in GitHub's web UI.

<img src="https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-it.gif" alt="Copying the example repository and releasing v0.3.0 from GitHub's web UI" width="880" />

The same recording as a video: [MP4](https://raw.githubusercontent.com/Twin-Fang/project-auto-wizard/main/assets/demo/try-it.mp4).

<Aside>
Prefer to look before you try? The example repository's [pull requests](https://github.com/Twin-Fang/project-auto-wizard-example/pulls?q=is%3Apr), [Actions runs](https://github.com/Twin-Fang/project-auto-wizard-example/actions) and [Releases](https://github.com/Twin-Fang/project-auto-wizard-example/releases) show releases that already ran.
</Aside>

<Steps>

1. **Copy the template.** On the [example repository](https://github.com/Twin-Fang/project-auto-wizard-example), click **Use this template** > **Create a new repository**. Choose your account as the owner, any name, and **Public**. Leave **Include all branches** off, then click **Create repository**.

   ✓ The new repository has `.github/workflows/`, `version.yml` and a README ending in `Latest Version : v0.x.y`. No release is created yet.

2. **Create the development branch.** Open the branch menu (it shows `main`), type `develop`, and choose **Create branch develop from main**.

   ✓ The branch menu lists `develop` and `main`.

3. **Commit a feature to `develop`.** On `develop`, open `src/greet.js`, click the pencil icon and change something, for example add `es: "Hola"` to `GREETINGS`. Click **Commit changes**, type the message `feat: greet in Spanish`, keep **Commit directly to the develop branch**, and commit.

   ✓ `develop` is one commit ahead of `main`, and that commit's message starts with `feat:`.

4. **Open the release PR.** Go to **Pull requests** > **New pull request**, set base `main` and compare `develop`, then click **Create pull request**.

5. **Watch it release.** Within about a minute `PROJECT-AUTO-CHANGELOG-CONTROL` runs on the PR: it confirms the next version, posts the release notes as a comment, updates `CHANGELOG.md` and merges the PR. A `feat:` commit raises the minor version.

   ✓ The PR shows **Merged** by `github-actions[bot]` and a comment such as `[0.3.0] ✨ Features`.

6. **Check the release.** Open **Releases**: a new `vX.Y.Z` release carries the notes. `CHANGELOG.md` has the entry and the README version line shows the new version.

</Steps>

<Aside type="caution">
**Check the commit message before you commit.** GitHub may replace your message with a suggestion from Copilot. The version is decided by the prefix: without `feat:` the release is a patch.

**Keep `develop`.** After the merge, GitHub offers to delete the `develop` branch. Leave it, so you can open the next release PR.
</Aside>

## Try more

- Commit a `fix:` and open another release PR from `develop`: only the patch version goes up.
- Commit `feat!: rename greet` (note the `!`): the major version goes up.
- Set `release_automerge: false` in `version.yml` on `develop`: the release PR is renamed to `chore(release): vX.Y.Z` and waits for you to merge it with any merge method.
- [Release flow](../../understand/release-flow/) explains each workflow, and [Quickstart](../quickstart/) installs it in your own project.

## If something does not happen

- **The terminal stays empty in the Codespace**: VS Code is in Restricted Mode. Click **Restricted Mode** in the status bar (or the banner at the top) and trust the folder.
- **`npm run try:release` says the Codespace "has no repository of its own yet"**: it was opened with the **Open in GitHub Codespaces** button on the template. Copy the template first (Part 2, step 1) and open the Codespace from your copy.
- **`npm run try:release` stops with "Nothing finished within the expected time"**: open the **Actions** tab of your copy. A run that is still queued finishes later; a failed run says in its last lines what blocked it.
- **No workflow runs on the PR**: check that the PR goes from `develop` to `main` and that the **Actions** tab of the repository is enabled.
- **The PR cannot be created ("entirely different commit histories")**: the copy was made with **Include all branches** on. Delete `develop` and create it again from `main` (step 2).
- **The PR is not merged automatically**: open the run in the **Actions** tab; the last lines say what blocked the merge, for example a branch protection rule, and what to change.
- **The CHANGELOG also lists older versions**: those come from the example repository's own releases, which the copy inherits.
