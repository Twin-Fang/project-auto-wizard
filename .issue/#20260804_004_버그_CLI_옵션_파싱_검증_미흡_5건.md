❗[버그][CLI 파싱] --paths·--type·--main-branch·--nexus 옵션 파싱/검증이 서로 비일관하거나 아예 없음 (5건)

🗒️ 설명
---

이슈 #11(전체 기능 실사용 QA)에서 발견된, CLI 옵션 파싱 계층(`src/cli/args.js`, `src/core/paths-resolve.js`)의 5가지 결함을 하나로 묶은 이슈입니다. 전부 "옵션 값에 대한 검증이 없거나, 유사한 두 옵션이 서로 다른 규칙으로 처리된다"는 공통 축입니다.

**① M3: `--paths`로 지정한 경로의 존재 여부를 전혀 검증하지 않음**

`node bin/project-auto-wizard.js --mode full --force --type react --paths "react=does-not-exist"`처럼 실제로 존재하지 않는 경로를 지정해도 에러 없이 `exit 0`으로 통과합니다. `version.yml`에 `project_paths: {react: "does-not-exist"}`가 검증 없이 그대로 기록되고, `does-not-exist` 디렉터리는 실제로 생성되지도 않습니다. `src/core/paths-resolve.js`에서 `--paths`로 이미 지정된 값은 `existsSync` 확인 없이 그대로 통과됩니다(대화형 직접입력 루프 228행에는 `existsSync` 체크가 있지만, `--paths` CLI 플래그 경로에는 없음). 이후 CI 워크플로우가 존재하지 않는 경로의 `package.json`을 참조하게 되어 실제 빌드 시점에야 실패가 드러납니다.

**② M4: 모노레포 경로 후보가 0개(감지 실패)와 2개 이상(모호함)이 동일하게 처리됨**

`--force`로 모노레포 타입 경로를 자동 확정할 때, 후보가 **0개**(예: flutter인데 `pubspec.yaml`만 있고 `lib/`가 없어 필터에서 걸러진 경우)든 **2개 이상**(예: react 마커가 있는 디렉터리가 2개)이든 똑같이 경고만 찍고 조용히 `.`(루트)로 확정합니다(`src/core/paths-resolve.js:178`: `say(⚠️ ${t} → 후보 ${candidates.length}개로 자동 확정 불가, 루트(.)로 기록 ...)`). 두 상황은 원인이 완전히 다른데(하나는 "못 찾음", 하나는 "너무 많음") 처리 결과 구분이 없습니다.

**③ L5: `--type`과 `--paths`의 타입명 내부 공백 처리 방식이 서로 다름**

`--type "re act"`는 `src/cli/args.js:50`의 `t.replace(/\s/g, "")`로 내부 공백을 전부 제거해 조용히 `"react"`로 정규화되어 정상 처리됩니다. 반면 `--paths "re act=."`의 타입명 파싱(112행)은 `.trim()`(양끝 공백만 제거)만 적용해 `"re act"`가 그대로 남고, `VALID_TYPES`에 없으므로 `CliError`로 즉시 거부됩니다. 같은 성격의 입력(타입명 문자열)에 대해 두 옵션이 서로 다른 정규화 규칙을 쓰는 비일관입니다.

**④ L6: `--main-branch ""` (빈 문자열 명시)가 미지정과 동일하게 처리됨**

사용자가 `--main-branch ""`를 **명시적으로** 지정해도, `src/index.js:249`의 `opts.mainBranch || existing?.branches?.main || ""`와 `src/core/branches.js:32`의 `mainBranch || defaultBranch || "main"`이 JS의 falsy 평가로 빈 문자열을 "값 없음"과 동일하게 취급해 자동 감지값(`main`)으로 조용히 폴백합니다. 에러도 경고도 없습니다.

**⑤ L7: `--nexus --no-nexus` 처럼 상호 모순되는 플래그를 동시에 지정해도 검증 없이 마지막 값이 적용됨**

`src/cli/args.js:77-78`의 파싱은 각 플래그를 만날 때마다 `result.includeNexus`를 단순 재할당합니다(`case "--nexus": includeNexus=true`, `case "--no-nexus": includeNexus=false`). 모순 검증 로직 자체가 없어 뒤에 온 플래그가 조용히 최종값이 됩니다. 사용자가 실수로 두 플래그를 동시에 넣었을 때 알아챌 방법이 없습니다.

🔄 재현 방법
---

**① M3**: `node bin/project-auto-wizard.js --mode full --force --type react --paths "react=does-not-exist"` → exit 0, `version.yml`에 미검증 경로 그대로 기록, 디렉터리는 실제로 없음(`ls does-not-exist` → No such file or directory)

**② M4**: (0개 케이스) flutter 타입인데 `lib/` 없이 `pubspec.yaml`만 있는 상태로 `--mode full --force --type flutter` / (2개 이상 케이스) react 마커가 있는 디렉터리 2개(`client/`, `admin/`)를 만든 상태로 `--mode full --force --type react` → 두 케이스 모두 경고 후 `project_paths`에 `.`로 조용히 기록

**③ L5**: `--type "re act"` (exit 0, react로 정규화되어 설치됨) vs `--paths "re act=."` (exit 1, `CliError: --paths에 지원하지 않는 타입: 're act'`)

**④ L6**: `--main-branch ""` → `version.yml`의 `main` 필드가 자동 감지값(`main`)으로 채워짐, 에러/경고 없음

**⑤ L7**: `--nexus --no-nexus --type spring` → `find .github/workflows -iname "*NEXUS*"` 결과 0건(마지막 플래그 `--no-nexus`가 적용됨), 에러/경고 없음

✅ 예상 동작
---

- `--paths`로 지정한 경로가 실제로 존재하지 않으면 최소한 경고, 이상적으로는 설치를 거부해야 합니다.
- 후보 0개와 2개 이상은 서로 다른 상황이므로 사용자에게 구분되어 전달되거나, 최소한 실패로 거부되어야 합니다.
- `--type`과 `--paths`는 타입명 문자열에 대해 동일한 정규화(공백 처리) 규칙을 적용해야 합니다.
- `--main-branch ""`처럼 빈 문자열을 명시적으로 지정한 경우와 아예 미지정한 경우는 구분되거나, 최소한 경고가 있어야 합니다.
- 상호 모순되는 플래그(`--nexus --no-nexus`)를 동시에 지정하면 에러로 거부하거나 최소한 경고해야 합니다.

🔍 원인 분석 및 수정 방향
---

**① M3**: `src/core/paths-resolve.js`에서 `--paths`로 지정된 값을 처리하는 분기에 `existsSync(join(root, path))` 검증을 추가하고, 실패 시 에러 또는 경고 처리 검토.

**② M4**: `src/core/paths-resolve.js:173-178` 부근 — `candidates.length === 0`과 `candidates.length > 1`을 별도 분기로 나눠 서로 다른 메시지/처리(예: 0개는 실패로 거부, 2개 이상은 경고 후 루트 확정 유지 또는 대화형 유도)를 검토.

**③ L5**: `src/cli/args.js:50`(`--type` 파서)과 112행(`--paths` 파서)의 정규화 로직을 통일 검토 — 둘 다 내부 공백을 허용하지 않는 것으로 맞추거나(에러), 둘 다 제거하는 것으로 맞춤(정규화).
```js
// src/cli/args.js:50 (--type)
t = t.replace(/\s/g, "");   // 내부 공백 전부 제거

// src/cli/args.js:112 (--paths)
const type = (eq >= 0 ? pair.slice(0, eq) : pair).trim();   // 양끝만 trim
```

**④ L6**: `src/index.js:249`, `src/core/branches.js:32`의 `||` 폴백 체인에서 빈 문자열과 `undefined`/`null`을 구분하는 로직(`??` 대신 명시적 체크, 또는 CLI 파싱 단계에서 빈 문자열 자체를 거부) 검토.

**⑤ L7**: `src/cli/args.js:77-78`에 `--nexus`/`--no-nexus`가 둘 다 지정된 경우를 감지하는 플래그(예: `nexusExplicitlySet` 카운터)를 추가해 모순 시 경고 또는 에러 검토.
