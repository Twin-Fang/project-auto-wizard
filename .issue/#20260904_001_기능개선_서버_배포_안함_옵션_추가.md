🚀[기능개선][배포] 서버 배포 방식 선택에 "배포 안 함(none)" 옵션 추가

### 어떤 문제를 해결하고 싶으신가요?

대화형 설치 마법사가 서버 배포 방식을 묻는 select 프롬프트는 지금 3개 선택지(`단일 서버 배포`, `무중단 배포(Nginx)`, `무중단 배포(Traefik)`)만 제공합니다. 내부 값은 `src/core/deploy-style.js:9-13`의 `DEPLOY_STYLES` 배열(`"simple"` / `"nginx"` / `"traefik"`, 기본값 `DEFAULT_DEPLOY_STYLE = "simple"`)에 정의되어 있고, `src/ui/prompts.js:88-98`의 `selectDeployStyle()`이 이 배열을 그대로 렌더링합니다.

문제는 서버 배포 자체를 하지 않는 프로젝트(프론트엔드 전용, 라이브러리 등)도 이 3개 중 하나를 강제로 골라야 한다는 점입니다. 지금 이 질문을 건너뛸 수 있는 유일한 경로는 `src/commands/interactive.js:122`의 `if (!includeNexus && !isDeployStyle(deployStyle))`로, Nexus(라이브러리 publish) 모드를 선택했을 때뿐입니다. 그 외 경우엔 항상 셋 중 하나를 골라야 하고, 그 선택값은 `deployFilter(style)`(`deploy-style.js:28-31`)을 통해 `src/core/copy/workflows.js`의 워크플로우 복사 필터링, `src/ui/env-plan.js`의 배포 관련 env 질문 노출, `src/core/version-yml.js`의 `OPT_DEPLOY_STYLE` 저장, `src/cli/args.js`의 `--deploy-style` CLI 옵션, `src/core/install-log.js:107`의 설치 요약 로그까지 이어집니다.

### 제안하는 해결 방법

기존 select에 4번째 선택지 `"서버 배포 안 함 — CD 워크플로우/배포 설정을 생성하지 않음"`(내부 값 `"none"`)을 추가합니다. 별도의 상위 Y/N 질문을 두지 않고 기존 4지선다 안에 통합하며, 기본 선택 커서는 계속 `"simple"`을 유지합니다.

다만 구현 시 반드시 주의해야 할 부분이 있습니다. `"none"`을 `DEPLOY_STYLES` 배열에 그대로 추가하면 안 됩니다. `isDeployWorkflow`(`deploy-style.js:20`, `(f) => DEPLOY_STYLES.some((s) => f.endsWith(s.suffix))`)와 `suffixOf`가 이 배열을 순회하는데, `"none"`에 빈 문자열 접미사를 넣으면 자바스크립트에서 `filename.endsWith("")`가 항상 `true`를 반환하기 때문에 모든 파일이 CD 워크플로우로 오판됩니다. 그 결과 `cleanupOtherDeployWorkflows`(`deploy-style.js:75`, `full.js:62`에서 매 설치마다 호출)의 keep 조건이 전부 false가 되어 설치된 워크플로우 전체가 삭제/`.bak` 처리되는 심각한 회귀가 발생합니다. 이를 피하려면 `"none"`을 `DEPLOY_STYLES`와 분리된 별도 상수로 두고, `isDeployStyle`(`deploy-style.js:17`)만 이 값을 포함하도록 확장하고, `deployFilter(style)`은 `style === "none"`일 때 `(f) => !isDeployWorkflow(f)`를 반환하는 별도 분기로 처리해야 합니다. 이렇게 하면 `isDeployWorkflow`/`suffixOf`/`activateDeployTrigger`/`cleanupOtherDeployWorkflows` 자체는 손대지 않고도 올바르게 동작합니다. 대신 `DEPLOY_STYLES`만 순회하는 `src/ui/prompts.js`의 옵션 목록과 `src/cli/args.js:80-85`의 `--deploy-style` 값 검증/오류 메시지에는 `"none"` 항목을 각각 명시적으로 추가해야 합니다.

또 하나 확인이 필요했던 지점은 `payload/workflows/spring/server-deploy/PROJECT-SPRING-PR-PREVIEW.yaml`입니다. 이 파일은 `server-deploy` 폴더에 있지만 `isDeployWorkflow` 기준으로는 CD 워크플로우가 아닌 별개의 축이라, `"none"`을 선택해도 별도 처리 없이는 그대로 설치되고 SSH_AUTH_METHOD/SSH_PORT 등 배포 관련 env 질문이 계속 노출됩니다. 이는 "배포 설정을 생성하지 않음"이라는 라벨과 맞지 않으므로, `"none"` 선택 시에는 `server-deploy` 폴더 전체(PR-PREVIEW 포함)를 제외하기로 했습니다. Nexus 모드가 `src/core/copy/workflows.js`에서 `includeNexus` 조건으로 이미 이 폴더 전체를 제외하고 있는 것과 동일한 패턴이며, `src/ui/env-plan.js:63` 근처의 필터 조건에도 같은 조건을 추가하면 됩니다. 단, 기존에 `simple`/`nginx`/`traefik`으로 설치되어 있던 프로젝트가 `"none"`으로 전환할 때 이미 설치된 PR-PREVIEW 파일은 이 폴더 제외 방식만으로는 능동적으로 정리되지 않고 남을 수 있습니다. Nexus 전환 시에도 동일한 제약이 있는 것으로 보여 이번에도 허용하되, README 등에 문서화가 필요합니다.

그 외 반영해야 할 지점들입니다.

- `src/commands/interactive.js:122`의 Nexus 특수 분기(배포 방식 질문 자체를 건너뛰는 로직)는 그대로 둡니다.
- `src/core/version-yml.js`는 `renderVersionYml`의 `deployStyle || DEFAULT_DEPLOY_STYLE` 폴백이 `"none"`(truthy 문자열)에는 걸리지 않으므로 별도 수정 없이 `OPT_DEPLOY_STYLE: "none"`이 정상적으로 저장·재사용될 것으로 보입니다.
- `src/cli/args.js`의 `--deploy-style`에 `none` 값을 추가하되, 플래그를 생략했을 때의 기본값은 하위 호환을 위해 계속 `simple`로 유지합니다. `src/cli/help.js:19`의 옵션 설명도 `simple | nginx | traefik | none`으로 갱신합니다.
- `install-log.js:107` 근처 설치 요약표에는 원값을 매핑하는 한 줄을 추가해 `"서버 배포: 없음"`으로 표기합니다.
- `status`/`doctor`/`uninstall` 명령은 조사 결과 배포 방식별 특수 로직이 원래 없어서(각각 status는 deployStyle을 애초에 화면에 표시하지 않고, doctor는 deploy 관련 검증이 없으며, uninstall/`removal-plan`은 방식과 무관하게 설치된 파일만 지우는 범용 로직) 추가 대응이 필요 없는 것으로 확인했습니다.
- `payload/version.yml.template`의 `# simple | nginx | traefik` 주석과 `README.md`의 배포 방식 설명도 `none`을 포함하도록 갱신합니다.
- `tests/node/deploy-style.test.js`에 `deployFilter("none")`이 CD 워크플로우 3종을 모두 제외하는지, `isDeployWorkflow`/`suffixOf` 동작이 `"none"` 추가 이후에도 무변경인지, `cleanupOtherDeployWorkflows`가 `"none"` 전환 시 기존 CD 3종을 정리하는지 검증하는 케이스를 추가하고(기존 :153의 "미지 값 → simple 폴백" 테스트와 충돌하지 않는지도 함께 확인), env-plan 테스트에도 `{deployStyle: "none"}`일 때 배포 전용 env 질문과 PR-PREVIEW 질문이 모두 스킵되는지 검증하는 케이스를 추가합니다.

이 설계는 `mattpocock-skills:grilling`으로 브레인스토밍하고 `claude-fable-5-1` 모델로 별도 리스크 검토까지 마친 상태이며, 위의 두 가지 구현 주의사항(배열 분리, PR-PREVIEW 폴더 제외)은 그 검토 과정에서 발견되었습니다.

### 고려한 다른 방법(선택)

기존 3지선다 select 앞에 "서버 배포를 진행하시겠습니까? (Y/N)" 같은 별도의 상위 게이트 질문을 하나 더 두고, Y일 때만 현재 3지선다를 보여주는 구조도 검토했습니다. 다만 질문 개수가 늘어나는 것에 비해 얻는 이점이 적어, 기존 select에 4번째 선택지로 통합하는 쪽을 택했습니다.

PR-PREVIEW를 `"none"`에서도 지금처럼 그대로 설치하고 안내 문구만 "PR 프리뷰는 이 선택과 무관하게 설치됩니다"로 덧붙이는 방법도 고려했습니다. 구현은 더 간단하지만, "배포 설정을 생성하지 않음"이라는 라벨과 실제 동작이 어긋나고 SSH 관련 env 질문이 여전히 남는다는 문제가 있어, `server-deploy` 폴더 전체를 제외하는 쪽을 최종적으로 선택했습니다.
