❗[버그][설치 엔진] 재실행/되돌리기 시 common 워크플로우·gitignore·version.yml·env 치환에서 데이터가 조용히 소실됨 (5건)

🗒️ 설명
---

이슈 #11(전체 기능 실사용 QA)에서 발견된, 설치/재설치/되돌리기 엔진(`src/core/copy/workflows.js`, `src/core/copy/gitignore.js`, `src/core/version-yml.js`, `src/core/wizard-env.js`, `src/commands/revert.js`)의 "재실행 시 사용자 데이터·설정을 보존해야 한다"는 공통 요구사항이 깨지는 5건을 하나로 묶은 이슈입니다.

**① H3 (최우선): common 워크플로우는 3지선 없이 무조건 덮어써짐**

README는 "재실행 시 충돌은 3지선(유지/백업 후 교체/참고본 추가)으로 처리"한다고 명시하지만, 실제로는 **타입별 워크플로우에만** 이 3지선이 적용됩니다. `VERSION-CONTROL`/`AUTO-CHANGELOG-CONTROL`/`RELEASE-PUBLISH` 같은 릴리스 자동화 핵심(common) 워크플로우는 사용자가 직접 수정했더라도 재실행 시 **무조건 덮어써집니다.**

`src/core/copy/workflows.js:76`의 주석이 이를 그대로 문서화하고 있습니다: `// (1) common — unchanged면 스킵, 아니면 무조건 덮어쓰기.` 실제 구현(80-93행)은 `decisions` Map을 전혀 참조하지 않고 `isUnchanged`만 검사해 changed면 즉시 `writeText`로 덮어씁니다. 반면 타입별 워크플로우는 190행에서 `applyDecision(decisions.get(f), ...)`로 `decisions`를 조회하고, 119행의 `applyDecision` 함수는 미지정(undefined)이면 기본값 `'skip'`으로 처리합니다 — 즉 CLI 명시 모드(`--mode full`)처럼 `decisions`가 항상 빈 Map인 경로에서는 **타입별 changed 파일은 구조적으로 항상 유지(skip)되지만 common changed 파일은 구조적으로 항상 덮어쓰기**됩니다. 대화형 마법사에서도 마찬가지입니다 — `listWorkflowConflicts`(대화형 3지선 수집 함수)가 common 디렉터리를 순회하지 않아, 사용자에게 common 파일 충돌은 애초에 질문조차 되지 않습니다.

재현으로 검증: 타입 워크플로우와 common 워크플로우 각각에 마커를 삽입한 뒤 동일한 `--mode full --force` 재실행 → 타입 파일은 마커 유지(KEPT), common 파일은 마커 사라짐(OVERWRITTEN).

**② M7: `.gitignore` 배너 블록 중간에 사용자가 줄을 끼워넣으면 제거가 부분적으로만 동작**

`src/core/copy/gitignore.js:14`의 `REQUIRED_ENTRIES = ["*.bak", "*.template.yaml"]`가 설치 배너 블록에 추가되는데, `removeAutoAddedEntriesFromGitignore`(84행)의 제거 로직(100-113행)은 배너 직후 `REQUIRED_ENTRIES`와 일치하는 라인이 **"연속"으로 이어지는 동안만** 소비합니다(108행: `isKnownEntry` 체크 후 불일치 시 루프 중단). 사용자가 `*.bak`과 `*.template.yaml` 사이에 자기 줄을 끼워넣으면, 그 지점에서 제거 루프가 멈춰 이후 항목(`*.template.yaml`)이 제거되지 않고 남습니다. (참고: 5행 주석에 이미 유사한 제약이 문서화되어 있습니다 — `REQUIRED_ENTRIES`가 옛 항목과 일치하지 않으면 배너 표시 없이 남는다는 내용.)

**③ M8: `version.yml`의 사용자 임의 필드가 재실행마다 소실됨**

`version.yml`은 `src/core/version-yml.js:129`의 `buildVersionYml`이 **매번 전체를 재생성**합니다(정규식 기반 라인 파서, `parseExisting`(50행)이 알려진 필드만 복원). 사용자가 `version.yml`에 직접 추가한 임의 필드(예: 커스텀 메타데이터)는 `--mode version` 재실행 한 번으로 완전히 사라집니다. 병합 로직이 아예 없습니다.

**④ L9: env 치환 값에 큰따옴표가 포함되면 YAML 구조가 깨짐**

`src/core/wizard-env.js:21`의 `setEnvLine(line, key, value)`가 사용하는 치환 정규식 `^(\s*${key}:\s*")[^"]*(")`는 첫 `"` 이후 다음 `"` 전까지만 매치하고, 치환할 `value`를 이스케이프 없이 그대로 삽입합니다. `@wizard ask`로 입력받은 값에 `"`가 포함되면(예: 사용자가 배포 경로에 따옴표를 넣는 경우) YAML 문자열 구조가 중간에 끊겨 후속 텍스트가 문자열 밖으로 노출되는 손상이 발생합니다.

**⑤ L12: `revert`가 payload에서 이름이 바뀌거나 삭제된 구버전 워크플로우 파일을 인식하지 못해 잔존시킴**

`src/commands/revert.js:11`의 `payloadWorkflowNames(payloadRoot)`는 **현재 설치된 npm 패키지의 payload**에 존재하는 워크플로우 파일명 집합만 계산하고, `planRevert`(23행)는 이 집합과 정확히 일치하는 파일만 제거 대상으로 삼습니다. 사용자가 과거 버전에서 설치한 뒤 이후 릴리스에서 payload의 파일명이 바뀌거나 파일 자체가 삭제됐다면, 그 구버전 파일은 현재 names 집합에 없으므로 `--mode revert`/`uninstall`을 실행해도 제거되지 않고 저장소에 그대로 남습니다.

🔄 재현 방법
---

**① H3**
1. `--mode full --force --type <타입>`으로 설치 (예: react)
2. 타입 전용 워크플로우 파일(예: `PROJECT-REACT-CI.yaml`)과 common 워크플로우(`PROJECT-COMMON-RELEASE-PUBLISH.yaml`)에 각각 임의 마커 텍스트 추가
3. 동일한 `--mode full --force --type <타입>` 재실행
4. 두 파일에서 마커 문자열이 남아있는지 `grep`으로 확인 → 타입 파일은 남고, common 파일은 사라짐

**② M7**
1. 배너 블록(`*.bak`, `*.template.yaml` 포함)이 존재하는 `.gitignore` 상태를 만듦(재현 방법은 실행자 측에서 `ensureGitignore()` 직접 호출로 확인 — 평범한 `full --force` 설치만으로는 backup/template 결정이 발생하지 않아 `.gitignore` 자체가 생성되지 않는 것도 별도 확인된 사실)
2. `*.bak`과 `*.template.yaml` 사이에 임의 줄 삽입
3. `--mode uninstall --force --purge-gitignore` 실행
4. `*.bak`은 제거되지만 삽입한 줄과 `*.template.yaml`은 그대로 남음

**③ M8**
1. `--mode full --force --type <타입>` 설치
2. `version.yml`에 `qa_custom_field: hello` 같은 임의 필드 수동 추가
3. `--mode version --force` 재실행
4. `version.yml`에서 해당 필드가 사라짐

**④ L9**: 코드 확인(재현 실행 없이 `src/core/wizard-env.js:21-34`의 정규식/삽입 로직으로 확정)

**⑤ L12**: 코드 확인(재현 실행 없이 `src/commands/revert.js:11-40`의 이름 집합 계산 로직으로 확정)

✅ 예상 동작
---

- README가 말하는 "3지선(유지/백업 후 교체/참고본 추가)"이 common 워크플로우에도 타입별 워크플로우와 동일하게 적용되어야 합니다.
- `.gitignore` 자동 추가 항목 제거는 사용자가 중간에 다른 줄을 끼워넣어도 배너가 관리하는 항목을 전부 인식해서 제거해야 합니다.
- `version.yml`의 사용자 임의 필드는 재실행 후에도 보존되어야 합니다(최소한 알려진 스키마 병합 방식으로).
- env 치환 값에 특수문자(큰따옴표)가 포함돼도 YAML 구조가 깨지지 않아야 합니다.
- `revert`/`uninstall`은 구버전에서 설치된 뒤 payload가 바뀐 워크플로우 파일도 인식해서 제거할 수 있어야 합니다(예: 별도 마커 주석으로 "이 도구가 설치함"을 식별하는 방식 검토).

**① H3**
```js
// src/core/copy/workflows.js:76-93 (현재 — decisions 미참조)
// (1) common — unchanged면 스킵, 아니면 무조건 덮어쓰기.
const commonDir = join(projectTypesDir, "common");
if (exists(commonDir)) {
  for (const filename of listYamlFiles(commonDir)) {
    ...
    if (existsSync(dst) && isUnchanged(body, readFileSync(dst, "utf8"), envOptsFor(...))) {
      // skip
    } else {
      writeText(dst, body); // ← decisions 조회 없이 무조건 덮어씀
    }
```

**② M7**: `src/core/copy/gitignore.js:100-113`의 `removeAutoAddedEntriesFromGitignore` — "연속 매치"가 아니라 배너 블록 전체 범위 안에서 `REQUIRED_ENTRIES` 각 항목을 개별적으로 찾아 제거하는 방식으로 변경 검토(배너 종료 마커 도입 등).

**③ M8**: `src/core/version-yml.js:50` `parseExisting`이 알려진 필드 외 나머지 라인을 별도로 보존했다가 `buildVersionYml`(129행) 재생성 시 다시 합치는 방식 검토.

**④ L9**: `src/core/wizard-env.js:21` `setEnvLine`에서 `value`를 YAML 문자열에 삽입하기 전 큰따옴표 등 특수문자를 이스케이프하는 로직 추가.

**⑤ L12**: `src/commands/revert.js:11` `payloadWorkflowNames` 방식 대신, 설치 시 각 워크플로우 파일에 "이 도구가 관리함" 식별 마커(주석)를 남기고 revert 시 그 마커로 대상을 판별하는 방식 검토(현재 파일명 집합 대조 방식의 근본적 한계).
