⚙️[기능추가][CLI] --mode uninstall 신설 — 대화형 체크리스트 기반 완전 삭제 지원

📝 현재 문제점
---

- npm으로 배포되는 `project-auto-wizard`는 사용자 프로젝트에 GitHub Actions 워크플로우, `.github/scripts/*.py`, `version.yml`, README 버전 섹션, `.gitignore` 항목, `.coderabbit.yaml`(opt-in) 등을 설치한다.
- 현재 `--mode revert`(`src/commands/revert.js`)가 존재하지만, payload 파일명과 정확히 일치하는 워크플로우·스크립트·`.coderabbit.yaml`만 제거하도록 의도적으로 보수적으로 설계되어 있다 (README `되돌리기(--mode revert)` 절).
- README 자동 버전 섹션(`<!-- AUTO-VERSION-SECTION` 마커로 식별 가능, `src/core/copy/readme.js`)과 `.gitignore` 자동 추가 항목(`project-auto-wizard: Auto-added entries` 배너로 식별 가능, `src/core/copy/gitignore.js`), `version.yml`은 "사용자 데이터"로 간주되어 `revert`가 전혀 건드리지 않는다.
- 결과적으로 사용자가 마법사를 완전히 걷어내고 싶을 때(도구 전환, 실험 종료 등) `revert` 실행 후에도 README·`.gitignore`에 흔적이 남아 수동으로 정리해야 한다. "설치는 잘 되는데 삭제는 애매하다"는 체감 불편의 원인이다.

🛠️ 해결 방안 / 제안 기능
---

- 기존 `--mode revert`는 지금 그대로 유지(하위 호환)하고, 별도의 `--mode uninstall`을 신설한다.
- **대화형(TTY) 실행 시** 체크리스트를 보여준다: 워크플로우/스크립트/coderabbit은 기본 선택(체크 상태), README 버전 섹션·`.gitignore` 자동 추가 항목·`version.yml`은 opt-in 체크박스로 제공한다. (설치 시 nexus/secret-backup/coderabbit이 opt-in인 것과 대칭되는 UX)
- **비대화형(`--force`) 실행 시**에는 안전한 최소 삭제(워크플로우·스크립트·coderabbit)만 기본 적용하고, README·gitignore·version.yml 삭제는 명시적 플래그(예: `--purge-readme`, `--purge-gitignore`, `--purge-version`)가 있을 때만 수행한다.
- 기존 `full`/`version`/`workflows`/`revert`와 동일하게 `--dry-run`을 지원해, 실제 삭제 전 무엇이 지워지는지 미리 보여준다.
- README·`.gitignore`는 이미 식별 가능한 마커/블록이 코드에 존재하므로, 오탐 없이 해당 구간만 안전하게 제거할 수 있다.

🧭 구현 가이드
---

- `src/cli/args.js`의 `parseArgs`: `mode` 유효값에 `uninstall` 추가, `--purge-readme` / `--purge-gitignore` / `--purge-version` 플래그 파싱 추가 필요.
- `src/index.js`의 `run()`: 71~85행의 `revert` 모드 분기(TTY/`--force` 게이트, `--dry-run` 처리)와 유사한 구조로 `uninstall` 모드 분기 추가.
- `src/commands/revert.js`의 `planRevert`/`runRevert`: 워크플로우·스크립트·coderabbit 제거 로직은 이미 순수 함수로 분리되어 있어, 새 uninstall 커맨드에서 그대로 재사용 가능할 것으로 추정됨(중복 구현 불필요).
- `src/core/copy/readme.js`의 `MARKER`(`<!-- AUTO-VERSION-SECTION`) 상수: 이 마커부터 추가된 섹션 끝까지 제거하는 대칭 함수(`removeVersionSectionFromReadme` 등) 신설 필요.
- `src/core/copy/gitignore.js`의 `REQUIRED_ENTRIES`/`entryExists`: `"project-auto-wizard: Auto-added entries"` 배너 이후 `REQUIRED_ENTRIES`에 해당하는 줄만 제거하는 대칭 함수 신설 필요.
- `src/commands/dry-run.js`의 `planDryRun`: `uninstall` 모드를 인식해 삭제 미리보기에 포함하도록 확장 필요.
- `src/ui/prompts.js`: 기존 설치 시 opt-in 질문(nexus/secret-backup/coderabbit) 로직이 있어, uninstall 체크리스트 프롬프트도 동일 패턴을 참고해 구현 가능할 것으로 추정됨.
- `src/cli/help.js`의 `HELP_TEXT`와 `README.md`의 `되돌리기(--mode revert)` 절(72행 부근): 새 모드·플래그 설명 추가 필요.

고려한 다른 방법(선택)
---

- **`revert`를 그대로 확장(신규 opt-in 플래그만 추가)**: 모드를 늘리지 않아 단순하지만, "삭제"와 "되돌리기(revert)"라는 서로 다른 개념이 한 명령에 섞여 발견성(discoverability)이 떨어질 수 있어 채택하지 않음.
- **문서화만 진행(코드 변경 없음)**: 구현 리스크는 없으나 설치 도구의 "완전 삭제 불가" 문제를 근본적으로 해결하지 못해 채택하지 않음.
