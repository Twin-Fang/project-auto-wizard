❗[버그][릴리스] release PR AI Summary 댓글이 확정 버전보다 이전 버전을 표시함

### 무슨 일이 있었나요?

**develop → main 릴리스 PR에서, PROJECT-AUTO-CHANGELOG-CONTROL이 버전을 확정한 뒤에도 AI Summary PR 댓글은 그보다 이전 버전을 계속 보여줍니다.**

실제로 겪은 사례: 릴리스 PR 후반에 자동 생성된 확정 커밋은 `chore(version): confirm v0.0.2 and update release docs` 였는데, 바로 그 아래 달려 있는 "🤖 AI Summary" 댓글에는 `[0.0.1]`이 표시되어 있었습니다. 반면 같은 릴리스로 갱신된 `CHANGELOG.md`에는 정상적으로 `## [0.0.2]`가 기록되어 있습니다. 한 화면 안에 "확정 커밋 버전(0.0.2) / AI Summary 버전(0.0.1) / CHANGELOG 버전(0.0.2)"이 서로 어긋나는 상태가 됩니다.

원인을 코드로 추적하면 다음과 같습니다.

- `PROJECT-COMMON-AI-PR-SUMMARY.yaml`과 `PROJECT-COMMON-AUTO-CHANGELOG-CONTROL.yaml`은 정확히 같은 이벤트(`pull_request: opened/synchronize/reopened`, base=`main`)에서 서로 독립적으로 실행됩니다.
- AI-PR-SUMMARY의 "Generate and post AI summary" 스텝은 그 순간 체크아웃된, 아직 bump되지 않은 `version.yml`을 `version_manager.py get`으로 읽어 즉시 댓글을 답니다.
- AUTO-CHANGELOG-CONTROL은 자신의 잡 안에서 버전을 bump하고 `chore(version): confirm v...` 커밋을 develop에 push합니다 — AI-PR-SUMMARY보다 항상 늦게 확정됩니다.
- 결정적으로, 이 확정 커밋은 "Commit release docs to the PR head branch" 스텝에서 checkout에 지정된 `secrets.GITHUB_TOKEN`으로 push됩니다. GitHub Actions 정책상 GITHUB_TOKEN으로 만든 push는 다른 워크플로우의 `pull_request: synchronize` 재트리거를 일으키지 않습니다(무한 루프 방지 정책). 그래서 확정 커밋이 push된 뒤 AI-PR-SUMMARY가 다시 실행되어 댓글을 정정할 기회가 구조적으로 없습니다. 즉 타이밍 우연이 아니라 release PR마다 항상 재현되는 구조적 버그입니다.
- 이 저장소는 이 GITHUB_TOKEN 비트리거 정책을 이미 알고 있습니다 — `NPM-PUBLISH.yaml` 헤더 주석이 이슈 #35로 명시하고 있고, 같은 AUTO-CHANGELOG-CONTROL의 "Enable automerge" 스텝과 `PROJECT-COMMON-RELEASE-PUBLISH.yaml`의 "Create GitHub Release" 스텝은 이를 피하려고 `secrets.WORKFLOW_PAT || github.token`을 사용합니다. 다만 "Commit release docs to the PR head branch" 스텝만 이 패턴이 빠져 있어, 이 push만 재트리거를 일으키지 못합니다. (`WORKFLOW_PAT` 시크릿 자체는 이미 등록돼 있습니다.)

### 기대했던 동작

- release PR에 게시되는 AI Summary 댓글은 항상 그 PR에서 실제로 확정(bump)된 버전과 일치해야 합니다.
- 릴리스 확정 커밋 / AI Summary / CHANGELOG.md 세 곳에 표시되는 버전이 항상 동일해야 합니다.

### 실행한 명령어

N/A — CLI 명령이 아니라 GitHub Actions 자동 트리거입니다. develop → main 릴리스 PR을 열면(또는 develop에 새 커밋을 push해 해당 PR을 synchronize하면) `PROJECT-AUTO-CHANGELOG-CONTROL`과 `PROJECT-AI-PR-SUMMARY`가 동시에 자동 실행되며 매번 재현됩니다.

### project-auto-wizard 버전

이 저장소(project-auto-wizard 자신)의 현재 상태 기준 — 최신 태그 `v0.3.0`, `version.yml`은 `mode: pr-flow`, `semver_auto: true`. 문제는 `payload/workflows/common/PROJECT-COMMON-AUTO-CHANGELOG-CONTROL.yaml` / `PROJECT-COMMON-AI-PR-SUMMARY.yaml` 템플릿 로직 자체에 있어, 이 템플릿을 설치한 모든 프로젝트에서 release PR마다 재현될 것으로 추정됩니다.

### OS

Linux (GitHub Actions `ubuntu-latest` 호스팅 러너)
