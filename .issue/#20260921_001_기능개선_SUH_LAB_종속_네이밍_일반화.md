🚀[기능개선][네이밍] SUH-LAB 종속 이름(@suh-lab 명령어·마커·파일명·출처 표기)을 일반 이름으로 변경

### 어떤 문제를 해결하고 싶으신가요?

이 프로젝트는 더 이상 SUH(원작자 개인 브랜드)에 종속된 프로젝트가 아닌데, 설치되는 워크플로우와 코드·문서에 `suh` 계열 이름이 그대로 남아 있습니다. `git grep -i suh` 기준으로 추적 파일 25개에서 확인했고, 성격별로 나누면 다음과 같습니다.

1. **댓글 명령어 `@suh-lab` (약 131곳)** — PR/이슈 댓글로 워크플로우를 트리거하는 사용자 대면 인터페이스입니다. `payload/workflows/spring/server-deploy/PROJECT-SPRING-PR-PREVIEW.yaml`, `payload/workflows/go/PROJECT-GO-PR-PREVIEW.yaml`, `payload/workflows/python/PROJECT-PYTHON-PR-PREVIEW.yaml`(`server build/destroy/status`)과 `payload/workflows/flutter/PROJECT-FLUTTER-SUH-LAB-APP-BUILD-TRIGGER.yaml`(`app/apk/ios build`)에 있습니다.
2. **마커 `Guide by SUH-LAB` (약 17곳)** — PR-PREVIEW 3종은 `ISSUE_HELPER_MARKER` 환경변수로, Flutter 트리거는 코드 안에서 이슈 댓글을 찾는 데 사용하고, `PROJECT-FLUTTER-ANDROID-TEST-APK.yaml`·`PROJECT-FLUTTER-IOS-TEST-TESTFLIGHT.yaml`은 오류 안내 문구에 씁니다. 그런데 이 레포의 `.github/scripts/issue_helper.py`(`payload/scripts/issue_helper.py`의 설치본)는 이 문구를 생성하지 않고 `<!-- project-auto-wizard issue helper -->` 마커와 `## Issue Helper` 제목으로 댓글을 만듭니다. 즉 이슈 댓글에서 브랜치를 찾는 기능은 지금도 동작하지 않는 원본 프로젝트의 잔재입니다. 추가로 Flutter 트리거의 브랜치 파싱 정규식은 `### 브랜치`만 받아서, issue helper가 쓰는 `### 브랜치명`과도 맞지 않습니다(PR-PREVIEW 3종은 `브랜치(?:명)?`으로 둘 다 받습니다).
3. **파일명·워크플로우명** — `PROJECT-FLUTTER-SUH-LAB-APP-BUILD-TRIGGER.yaml`과 그 안의 `name: PROJECT-Flutter-SUH-LAB-App-Build-Trigger`. `src/`와 `tests/`에서 이 파일명을 참조하는 곳은 없습니다.
4. **heredoc 센티널 `__SUH_FILE_CONTENT_EOF__`, `__SUH_SECRET_CHECK_EOF__`** — `payload/workflows/common/secret-backup/PROJECT-COMMON-SECRET-FILE-UPLOAD.yaml`, 이를 미치환 검사에서 제외하는 `src/core/verify.js`의 `SENTINEL_RE`, `tests/node/verify.test.js`.
5. **폴더 `docs/suh-template/hypercortex/`** — 4개 문서이며 내용은 npm `--provenance` 관련 설계로 suh와 무관합니다. 폴더명만 남은 상태이고 이 경로를 참조하는 곳은 없습니다.
6. **원본·라이선스 출처 표기** — `SUH-DEVOPS-TEMPLATE (Cassiiopeia/projectops)` 원본 표기가 `docs/DESIGN-SPEC.md`, `docs/BRAINSTORMING.md`, `docs/2026-07-08-projectops-oss-design.md`, `docs/HANDOFF.md`, `docs/IMPLEMENTATION-PLAN.md`, `docs/superpowers/specs/2026-07-25-osscontest-scope-design.md`에 있고, 코드 docstring에도 있습니다(`.github/scripts/version_manager.py`, `payload/scripts/version_manager.py`, `tests/py/test_sh_equivalence.py`). 이 프로젝트가 원본이므로 출처·라이선스 주장은 정리 대상입니다. `LICENSE` 파일에는 해당 내용이 없어 변경할 것이 없습니다.
7. **`projectops` 식별자** — `.github/scripts/changelog_manager.py`와 `payload/scripts/changelog_manager.py`(동일 복사본)의 "projectops 컨벤션" 주석, `tests/py/test_changelog_fallback.py`·`tests/py/test_classify_bump.py`의 테스트 함수명, `tests/py/test_sh_equivalence.py`의 환경변수 `PROJECTOPS_SH_REF`.
8. **주석 예시의 `Suh-Web/`** — `PROJECT-SPRING-PR-PREVIEW.yaml`에 주석으로 남은 원작자 프로젝트 모듈명 예시 2줄. 기존 `tests/node/payload-example-values.test.js`의 `FORBIDDEN` 검사는 주석 줄을 제외하므로 지금까지 걸리지 않았습니다.

이름 정리와 함께 처리할 운영 항목이 하나 있습니다. 이 레포에 설치된 issue helper(`.github/workflows/PROJECT-COMMON-ISSUE-HELPER.yaml`)는 `ISSUE_HELPER_CREATE_BRANCH`가 `"false"`라서 이슈를 만들어도 브랜치가 자동 생성되지 않고 브랜치명만 댓글로 안내됩니다(#68에서 옵트인으로 전환된 기본값). 또 `ISSUE_HELPER_BASE_BRANCH`가 `main`이라 그대로 켜면 `CONTRIBUTING.md`의 `develop` 기준과 어긋납니다.

### 제안하는 해결 방법

논의를 거쳐 아래와 같이 확정했습니다. 하나의 이슈, 하나의 브랜치, 하나의 PR로 진행하고 책임별로 커밋을 나눕니다. 하위 호환(예전 `@suh-lab` 동시 인식)은 두지 않습니다.

**결정 사항**

- 댓글 명령어 접두사는 `@suh-lab`을 `/wizard`로 바꿉니다. 서브커맨드(`server build|destroy|status`, `app|apk|ios build`), 어순 무관 매칭, 대소문자 처리는 그대로 두고 접두사만 치환합니다.
- 마커는 `Guide by SUH-LAB`을 이 레포 issue helper의 실제 마커 `<!-- project-auto-wizard issue helper -->`로 교체합니다. 안내 문구의 "Guide by SUH-LAB 댓글"은 "Issue Helper 댓글"로 바꿉니다. 이 변경으로 이슈 댓글 브랜치 조회가 처음으로 실제 동작하게 됩니다.
- Flutter 트리거의 브랜치 파싱 정규식을 `### 브랜치명`도 받도록 보정해 PR-PREVIEW 3종과 맞춥니다.
- Flutter 트리거 파일은 `PROJECT-FLUTTER-APP-BUILD-TRIGGER.yaml`로, 워크플로우 `name:`은 `PROJECT-Flutter-App-Build-Trigger`로 바꿉니다.
- heredoc 센티널은 `__WIZARD_*__`로 바꿉니다.
- `docs/suh-template/hypercortex/`는 `docs/hypercortex/`로 이동합니다.
- 출처·라이선스 표기는 `원본:` 헤더 등 출처 포인터 줄과 라이선스·저작 서술만 삭제하고, 나머지 설계 서술은 과거 기록으로 유지합니다. 코드 docstring의 `SUH-DEVOPS-TEMPLATE` 언급은 "원본 bash 구현(version_manager.sh)" 같은 일반 표현으로 바꿉니다.
- `projectops` 식별자는 코드 수준만 정리합니다. 주석 문구, 테스트 함수명, `PROJECTOPS_SH_REF`를 `VERSION_MANAGER_SH_REF`로 바꿉니다.
- 주석 예시의 `Suh-Web`은 일반 자리표시자로 교체합니다.
- 이 레포의 issue helper 설치본에서 `ISSUE_HELPER_CREATE_BRANCH`를 `"true"`로, `ISSUE_HELPER_BASE_BRANCH`를 `develop`으로 바꿔 이슈 생성 시 브랜치가 자동 생성되도록 합니다. `payload/` 템플릿 기본값은 바꾸지 않습니다. `issues` 이벤트 워크플로우는 기본 브랜치(`main`)의 버전으로 실행되므로 릴리스에 포함된 이후 생성되는 이슈부터 적용됩니다.

**구현 가이드 (파일 경로 + 심볼 + 변경 요약)**

- `tests/node/payload-example-values.test.js`: 재유입 방지 가드를 먼저 추가합니다(RED). `payload/`, `src/`, `.github/`를 대상으로 주석 줄까지 포함해 `suh`와 `projectops`(대소문자 무시)가 없는지 검사합니다. `tests/`는 가드 자신이 패턴 문자열을 담고 있어 제외하고, `docs/`는 과거 기록이라 제외합니다. 기존 `FORBIDDEN` 목록·`allWorkflowFiles` 헬퍼와 같은 방식으로 작성합니다.
- PR-PREVIEW 3종: 명령어 감지 조건(`contains(github.event.comment.body, ...)`), 명령어 파싱 bash 정규식, 사용자에게 보이는 안내 표와 다시 시도 문구, `ISSUE_HELPER_MARKER` 값을 각각 새 접두사와 새 마커로 교체합니다.
- `PROJECT-FLUTTER-APP-BUILD-TRIGGER.yaml`(파일명 변경은 `git mv`): 댓글 명령어 감지와 `apk`·`ios`·`app` 파싱 정규식, 이슈 댓글 조회의 `includes(...)` 마커, 브랜치 추출 정규식을 위 결정에 맞춰 수정하고 주석 설명도 함께 갱신합니다.
- `PROJECT-FLUTTER-ANDROID-TEST-APK.yaml`, `PROJECT-FLUTTER-IOS-TEST-TESTFLIGHT.yaml`: 실패 안내 문구의 "Guide by SUH-LAB"만 교체합니다.
- `PROJECT-COMMON-SECRET-FILE-UPLOAD.yaml`, `src/core/verify.js`(`SENTINEL_RE`), `tests/node/verify.test.js`: 센티널 접두사를 `__WIZARD_`로 통일하고, 오탐이 없는지 테스트로 확인합니다.
- `.github/scripts/`와 `payload/scripts/`의 `changelog_manager.py`, `version_manager.py`: 동일 복사본이므로 양쪽을 똑같이 수정하고 `diff`로 일치를 확인합니다.
- `tests/py/test_sh_equivalence.py`, `test_changelog_fallback.py`, `test_classify_bump.py`: 환경변수명·테스트 함수명·docstring을 정리합니다.
- `docs/` 문서 6개: 위 출처 포인터 줄과 라이선스 서술만 삭제합니다.
- `.github/workflows/PROJECT-COMMON-ISSUE-HELPER.yaml`: `env`의 `ISSUE_HELPER_CREATE_BRANCH`와 `ISSUE_HELPER_BASE_BRANCH` 두 값만 변경합니다. `@wizard ask:false` 마커 주석과 `contents: write` 권한은 그대로 둡니다.

**검증과 릴리스**

- `npm test`와 python 테스트를 전부 실행합니다. 접두사 정규식은 커밋하지 않는 일회성 스크립트로 새 명령어가 매칭되는지 확인합니다.
- 커밋 메시지는 한국어로 작성합니다. 사용자 대면 breaking인 명령어 접두사·마커 교체 커밋만 `feat:` 타입을 쓰고 breaking 내용을 본문에 명시합니다. 나머지는 성격에 맞게 `test:`, `refactor:`, `chore:`, `docs:`, `ci:`를 씁니다. `!` 마커는 쓰지 않습니다(`!`를 쓰면 자동 버전 로직이 major로 올려 0.9.1이 1.0.0이 되기 때문). 결과 버전은 0.10.0으로 예상합니다.
- 릴리스 노트에 예전 `@suh-lab` 명령어와 옛 Flutter 트리거 파일이 이미 설치된 저장소는 재설치 후 옛 파일을 직접 정리해야 한다고 안내합니다.

**변경하지 않는 것**

- `LICENSE`(이미 해당 내용 없음)
- 과거 spec·plan 문서 안의 옛 파일명 서술(당시 사실 기록)
- `docs/projectops/` 폴더와 `docs/2026-07-08-projectops-oss-design.md` 파일명
- `.gitignore` 대상 디렉토리(`.issue/`, `.superpowers/`, `.worktrees/`)
- README의 명령어 안내(원래 `@suh-lab` 안내가 없어 이번에도 추가하지 않음)
- `payload/` issue helper 템플릿의 `ISSUE_HELPER_CREATE_BRANCH` 기본값(`"false"`)과 `# @wizard ask:false` 마커

### 고려한 다른 방법(선택)

- **접두사 `@auto-wizard`**: `auto-wizard`는 실제 GitHub 사용자(2024-08-18 가입)라 명령어 댓글마다 그 계정에 멘션 알림이 갑니다. 짧은 `@` 핸들 대부분(`@paw`, `@wiz`, `@autowizard` 등)도 이미 다른 사용자가 쓰고 있어 제외했습니다.
- **접두사 `@project-auto-wizard`**: 같은 이름의 Organization이 존재하지만 소유 여부를 확인하지 못했습니다.
- **`@suh-lab`과 새 접두사를 함께 인식하는 이중 매칭**: 원작자 이름을 계속 남기게 되고 정규식이 복잡해져 0.x 단계에서는 도입하지 않습니다.
- **`feat!:` 로 breaking 표시**: 자동 버전 로직이 1.0.0으로 올리게 됩니다. 1.0.0 선언은 이름 정리와 별개의 결정으로 보고 제외했습니다.
- **출처·라이선스 표기를 과거 문서까지 전부 재작성**: 당시 설계 기록의 정확성을 해치고 변경 범위가 과해서, 출처 포인터 줄과 라이선스 서술만 삭제합니다.
- **`payload/` 템플릿 기본값도 `"true"`로 변경**: 모든 사용자의 기본 동작이 바뀌고 #68에서 이슈를 열 때마다 브랜치가 생성되는 것을 막으려 옵트인으로 되돌린 결정을 뒤집게 되어 제외했습니다. 이 레포의 설치본만 바꿉니다.
- **이슈·PR 분할(명령어·마커 변경과 나머지 정리 분리)**: 브랜치가 이슈 번호에 묶이고 자동 종료 정규식도 있어 이슈가 둘로 갈라지는 부담이 커서 하나로 진행하기로 했습니다.
