❗[버그][CLI 안전장치] 잘못된 --mode 값이 검증 없이 통과되고, 아무것도 설치 안 됐는데도 성공 화면이 뜸

🗒️ 설명
---

이슈 #11(전체 기능 실사용 QA)에서 발견된, `src/index.js`의 모드 디스패치 진입점과 `src/ui/summary.js`/`src/ui/banner.js`의 요약 출력에 몰려있는 3개의 관련 결함을 하나로 묶은 이슈입니다. 전부 "CLI가 실제로 무엇을 했는지와 화면에 뜨는 메시지가 일치하지 않는다"는 같은 축의 문제입니다.

**① `--mode` 값 화이트리스트 검증 누락 (+ 원격 부수효과)**

`node bin/project-auto-wizard.js --mode ful --force --type node` 처럼 `--mode` 값에 오타가 있어도 CLI는 이를 전혀 검증하지 않습니다. `src/index.js:299`의 `switch (opts.mode)`는 `full`/`version`/`workflows`만 처리하고, `default`(303행)는 그냥 아무것도 안 하고 넘어갑니다(`// 알 수 없는 모드 → .sh와 동일하게 복사 0건, 에러 아님` — 레거시 `.sh` 스크립트와 동일 동작을 의도적으로 유지한 주석이 있습니다).

문제는 이 `switch`에 도달하기 **전에** 이미 실제 부수효과가 발생한다는 것입니다. `src/index.js:254-259`에서 원격 브랜치 목록을 조회하고, `develop` 브랜치가 원격에 없으면 **로컬에 생성한 뒤 실제로 push까지** 해버립니다(`ensureDevelopBranch`). 이 로직은 `opts.mode`가 무엇이든 상관없이(모드 값 검증 이전에) 실행됩니다. 즉 오타 하나로 아무 워크플로우도 설치되지 않았는데 원격 저장소에는 `develop` 브랜치가 실제로 생기는 부작용이 발생합니다.

**② TTY 환경에서 `--force` 없이도 확인 절차 없이 즉시 설치**

`node bin/project-auto-wizard.js --mode full --type node`(TTY, `--force` 미지정)를 실행하면 어떤 확인 질문도 없이 즉시 설치가 완료됩니다. `src/index.js:225`의 게이트는 `if (!opts.force && !opts.dryRun && !process.stdout.isTTY)`로, **비TTY일 때만** 에러를 냅니다 — TTY면 그냥 통과합니다. 더 결정적으로, `src/index.js:268`에서 `createContext({ ..., force: true, ... })`로 **`force`가 사용자 입력과 무관하게 무조건 `true`로 하드코딩**됩니다. TTY용 확인 절차 자체가 이 경로(`--mode full` 등 명시 모드)에는 없습니다 — 대화형 3지선 질문은 `--mode interactive`/`runInteractive` 전용 별도 경로에만 있습니다.

**③ `printSummary()`가 실제 실행 결과를 검증하지 않고 항상 성공 화면을 출력**

①의 오타 모드 재현 시, `version.yml`/`README.md`/`.github/` 어느 것도 실제로 생성되지 않았는데도 화면에는 다음이 그대로 출력됩니다:

```
추가된 파일:
  📄 version.yml (버전: 1.0.0, 타입: node)
  📝 README.md (버전 섹션 추가)

추가된 워크플로우:
  🔧 .github/scripts/
     ├─ version_manager.py
     └─ changelog_manager.py
```

`src/index.js:307-317`을 보면 `switch`가 `default`로 빠져 `result`가 `null`이어도 `printSummary()`는 무조건 호출됩니다. `printSummary()`(`src/ui/summary.js:10`)는 인자로 받은 `counters`만 참조하고 실제 파일시스템 상태를 검증하지 않습니다. 별개로, `src/ui/summary.js:69-89`의 "📦 새로 설치됨" 목록 로직도 같은 계열 결함입니다 — `.github/workflows/` 디렉터리를 **현재 시점 기준으로 재스캔**해 해당 prefix로 시작하는 파일을 전부 "새로 설치됨"으로 나열합니다(`workflowsCopied` 카운트(86행, `counters.workflows` 사용)와 목록 항목 수는 서로 다른 소스라 개수도 안 맞습니다). `--force` 재실행 시 실제로는 `skip`된(안 건드린) 파일까지 "새로 설치됨"으로 표시됩니다.

🔄 재현 방법
---

**① 잘못된 --mode 값**
1. 임시 저장소에 `origin`을 로컬 bare 저장소(main만 존재)로 연결
2. `node bin/project-auto-wizard.js --mode ful --force --type node` 실행
3. `exit code: 0`, `.github/workflows/`는 비어있음을 확인
4. `git branch -a`로 로컬에 `develop`이 생겼는지, `git -C <bare-repo> branch`로 원격에도 `develop`이 push됐는지 확인 → 실제로 생김

**② TTY에서 --force 없는 명시 모드**
1. `script -q script.log node bin/project-auto-wizard.js --mode full --type node` (의사 TTY, `--force` 없음, stdin 빈 줄)
2. 확인 질문 없이 즉시 `.github/workflows/`에 파일 5개, `version.yml`, `README.md`가 생성됨을 확인

**③ 거짓 성공 화면**
1. ①의 시나리오를 그대로 재현
2. `output.log`에는 "✨ Setup Complete!"와 함께 파일 생성 완료 메시지가 뜨지만, 실제 디렉터리(`ls -la`)에는 `version.yml`/`README.md`/`.github/`가 전혀 없음을 대조 확인

✅ 예상 동작
---

- `--mode`에 지원하지 않는 값이 오면 명확한 에러 메시지와 함께 즉시 종료(exit 1)되어야 하며, 원격에 어떠한 브랜치 부수효과도 있으면 안 됩니다.
- TTY든 아니든 `--force` 없이 명시 모드(`full`/`version`/`workflows`)를 실행하면 최소한 확인 절차(질문 또는 거부)가 있어야 합니다.
- `printSummary()`는 실제로 파일이 생성/변경됐는지를 반영해서 출력해야 하며, 아무것도 안 했다면 "실패" 또는 "변경 없음"으로 표시해야 합니다. "새로 설치됨" 목록도 이번 실행에서 실제로 복사된 파일만 나열해야 합니다.

🔍 원인 분석 및 수정 방향
---

**① 모드 값 검증**
- `src/index.js:299` 이전(가급적 인자 파싱 직후, `src/cli/args.js` 또는 `src/index.js` 상단)에 `opts.mode`가 알려진 값(`full`/`version`/`workflows`/`revert`/`uninstall`/`status`/`doctor`/`purge`/`interactive`) 중 하나인지 검증하는 화이트리스트 체크를 추가해야 합니다. 검증 실패 시 브랜치 조회/`ensureDevelopBranch` 호출(254-259행)을 포함한 이후 모든 로직을 건너뛰고 즉시 에러로 종료해야 합니다.
- 참고 코드:
  ```js
  // src/index.js:254-259 (현재)
  const remoteBranches = await detectRemoteBranches(cwd);
  if (remoteBranches.length && !remoteBranches.includes(branches.develop)) {
    await ensureDevelopBranch({
      develop: branches.develop, remoteBranches, confirm: null, cwd,
      ...
  ```
  이 블록이 실행되기 전에 모드 검증이 선행되어야 합니다.

**② TTY 확인 절차**
- `src/index.js:225-228`의 가드(`if (!opts.force && !opts.dryRun && !process.stdout.isTTY)`)를 TTY 여부와 무관하게 `--force`가 없으면 최소한의 확인(예: readline 기반 y/n 질문, 또는 명시 모드에서도 `--force` 필수화)으로 바꾸는 방향을 검토해야 합니다. 또는 최소한 `src/index.js:268`에서 `force: true`를 무조건 하드코딩하는 부분을 실제 `opts.force` 값을 반영하도록 수정해야 합니다.
  ```js
  // src/index.js:268 (현재)
  mode: opts.mode, force: true, types, version, versionCode, branch,
  ```

**③ printSummary 정확성**
- `src/index.js:307-317`에서 `result`가 `null`(알 수 없는 모드로 아무 작업도 안 한 경우)이면 `printSummary()`를 호출하지 않거나, "아무 것도 설치되지 않았습니다" 같은 별도 메시지를 출력하도록 분기해야 합니다.
- `src/ui/summary.js:69-89`의 "📦 새로 설치됨" 목록은 디렉터리 재스캔 대신, 실제 copy 엔진(`src/core/copy/workflows.js`)이 반환하는 결과(신규/skip/backup/template 분류)를 그대로 전달받아 표시하도록 데이터 흐름을 바꿔야 합니다. `workflowsCopied`(18행, `counters.workflows`) 카운트와 목록 항목 수의 소스를 일치시켜야 합니다.
