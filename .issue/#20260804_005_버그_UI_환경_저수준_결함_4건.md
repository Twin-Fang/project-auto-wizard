❗[버그][UI/환경] stdin 종료 미처리·색상 비일관·대화형 메뉴 누락·jq 폴백 무경고 (4건)

🗒️ 설명
---

이슈 #11(전체 기능 실사용 QA)에서 발견된, UI/환경 처리 계층(`src/ui/readline-engine.js`, `src/ui/ansi.js`, `src/ui/summary.js`, `src/ui/prompts.js`, `src/core/detect.js`)의 4가지 결함을 하나로 묶은 이슈입니다. 각각은 독립적이지만 전부 "저수준 환경 처리가 문서화된 기대와 다르다"는 성격입니다. 개별 심각도는 상대적으로 낮지만 실사용 시 혼란을 유발할 수 있어 정리합니다.

**① L1/M11: 대화형 입력 중 stdin 종료(EOF/Ctrl+D)를 처리하지 않음**

`src/ui/readline-engine.js`를 전체 검색해도 `stdin.on("end", ...)` 핸들러가 없습니다(`stdin.on("keypress", ...)`만 두 곳에 존재 — 79행, 214행). 사용자가 대화형 프롬프트 도중 Ctrl+D를 누르거나 stdin이 예기치 않게 끊기면(SSH 연결 끊김 등) 아무 반응 없이 무한 대기할 가능성이 있습니다.

**② L2: `NO_COLOR`/비TTY 환경에서 색상 처리가 화면 영역마다 다름**

`src/ui/banner.js`의 배너 출력은 `src/ui/ansi.js:13`의 `paint(s, color) => \`${color}${s}${A.reset}\`` 를 무조건 호출합니다 — `ansi.js` 전체에 `NO_COLOR`나 `isTTY` 가드가 전혀 없습니다. 반면 `src/ui/summary.js:14`의 요약 출력은 `process.stderr.isTTY`만으로 색상을 게이팅합니다(`NO_COLOR`는 여기서도 확인 안 함). 즉 같은 실행 안에서 배너는 항상 색을 칠하고 요약은 TTY 여부만 보는 두 갈래 로직이 공존합니다. `NO_COLOR=1` + 비TTY(파일 리다이렉트) 환경에서 실제로 배너 출력에 ESC(0x1b) 바이트가 섞이는 것을 확인했습니다.

**③ L3: 대화형 최상위 메뉴에 `status`/`doctor` 모드가 노출되지 않음**

README(127행)는 `--mode`로 `full | version | workflows | revert | uninstall | status | doctor` 7종을 문서화하고 "(기본: 대화형)"이라 명시합니다. 그런데 `src/ui/prompts.js`(13-17행)의 최상위 메뉴 choices는 `full`/`version`/`workflows`/`revert`/`uninstall` 5개뿐입니다. `status`/`doctor` 문자열은 메뉴 선택지 어디에도 없고(유일한 매치는 85행의 `status-cards.js` import 문), `src/commands/interactive.js`에도 매치가 없습니다. README에는 이 둘이 "읽기 전용" 모드로 별도 소개(146-153행)되어 있지만, 대화형 메뉴에는 노출되지 않아 사용자가 CLI 플래그를 미리 알아야만 접근 가능합니다. `interactive.js`/`prompts.js`에 의도적으로 제외한다는 주석·근거는 발견되지 않았습니다.

**④ L4: jq 미설치 환경에서 이미 파싱된 버전 값을 버리고 경고 없이 잘못된 값으로 폴백**

`src/core/detect.js:38`의 `detectVersionFromFiles`는 `readJson("package.json")`으로 이미 순수 Node `JSON.parse`를 통해 파싱된 `pkg.version`을 가지고 있음에도, `hasJq`(40행)가 `false`면 이 값을 그냥 버리고 `build.gradle`/`pubspec.yaml`/`pyproject.toml` grep → git tag → 최종 하드코딩 `"0.0.1"` 순으로 폴백합니다. jq는 실제로 `package.json` 파싱에 전혀 쓰이지 않는데도 이미 확보된 값을 차단하는 불필요한 게이트이며, 폴백 시 사용자에게 아무 경고도 없이 잘못된 버전(`0.0.1`)이 조용히 `version.yml`에 기록됩니다.

✅ 예상 동작
---

- EOF(Ctrl+D) 시그널을 명시적으로 처리하는 `stdin.on("end", ...)` 핸들러가 있어야 하며, 최소한 무한 대기 없이 종료되어야 합니다.
- `NO_COLOR`/비TTY 환경에서는 화면 어디든 일관되게 색상 코드가 섞이지 않아야 합니다.
- 대화형 최상위 메뉴에서도 `status`/`doctor`(읽기 전용 모드)에 접근할 수 있어야 자연스럽습니다.
- jq 미설치 환경에서도 이미 파싱 가능한 `package.json`의 버전은 정상 감지되거나, 최소한 폴백 시 사용자에게 명확한 경고가 있어야 합니다.

🔍 원인 분석 및 수정 방향
---

**① L1/M11**: `src/ui/readline-engine.js`의 키 입력 세션(`keySession`, `text` 등 — 79행/214행 `stdin.on("keypress", ...)` 등록 지점)에 `stdin.on("end", () => { ... })` 핸들러를 추가해 EOF 시 안전하게 reject/resolve하도록 수정 검토.

**② L2**: `src/ui/ansi.js:13`의 `paint()`에 `NO_COLOR` 환경변수와 `process.stdout.isTTY`(또는 stderr, 사용처에 맞게) 체크를 추가하고, `src/ui/summary.js:14`의 게이팅 로직과 통일해 두 로직을 하나의 공용 헬퍼로 합치는 방향 검토.

**③ L3**: `src/ui/prompts.js`의 최상위 메뉴 choices(13-17행)에 `status`/`doctor`를 (읽기 전용임을 표시하며) 추가하고, `src/commands/interactive.js`에서 선택 시 해당 커맨드를 호출하도록 분기 추가 검토.

**④ L4**: `src/core/detect.js:38-40`의 `detectVersionFromFiles`에서 `hasJq` 게이트를 `package.json` 케이스에는 적용하지 않도록(이미 Node `JSON.parse`로 파싱했으므로 jq가 불필요) 조건 분기 수정 검토. 다른 매니페스트(build.gradle 등)에서 jq가 실제로 필요한 케이스만 게이트 유지.
