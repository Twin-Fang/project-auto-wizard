🚀[기능개선][대화형] 브랜치 전략(pr-flow/trunk-based)을 명시적으로 선택하는 단계 추가

### 어떤 문제를 해결하고 싶으신가요?

지금 대화형 설치 마법사는 `src/commands/interactive.js:194-196`에서 "릴리스 브랜치를 선택하세요"와 "개발 브랜치를 선택하세요 (기본: develop)"를 순서대로 물어봅니다. `src/core/branches.js:34`의 `resolveBranchConfig()`가 `main === develop ? "trunk-based" : "pr-flow"`로 모드를 정하기 때문에, **두 질문에 같은 브랜치명을 입력해야만** trunk-based(개발 브랜치 없이 main 하나만 쓰는 방식)로 전환됩니다.

문제는 이 규칙이 화면 어디에도 미리 안내되지 않는다는 점입니다. "개발 브랜치를 선택하세요"라는 질문의 기본값이 `develop`이라, 사용자는 자연스럽게 그 값을 그대로 받아들이게 되고 pr-flow로 가게 됩니다. trunk-based를 쓰려면 "질문 두 개에 같은 이름을 입력하면 모드가 바뀐다"는 걸 미리 알고 있어야만 하는데, 이 사실은 입력을 마친 **후에야** `src/commands/interactive.js:198-199`의 `io.note?.("릴리스 브랜치 = 개발 브랜치 → trunk-based 모드로 설치합니다 (RELEASE-PUBLISH 단독).", "브랜치 모드")` 안내로 사후에만 나타납니다.

### 제안하는 해결 방법

두 개의 개별 브랜치명 질문 대신, 브랜치 전략 자체를 먼저 명시적으로 선택하게 바꾸는 것을 제안합니다. 예를 들어:

1. "브랜치 전략을 선택하세요: 1) develop → main PR 흐름(pr-flow) 2) main 단일 브랜치(trunk-based)"를 먼저 묻는다.
2. pr-flow를 선택하면 지금처럼 "릴리스 브랜치"/"개발 브랜치"를 각각 입력받는다.
3. trunk-based를 선택하면 "릴리스 브랜치(=유일한 브랜치)"만 입력받고, 개발 브랜치 질문 자체를 생략한다(내부적으로 `develop = main`으로 설정).

이렇게 하면 두 모드의 존재와 차이를 사용자가 미리 알고 선택하게 되고, "같은 이름을 두 번 입력해야 한다"는 암묵적 규칙에 의존하지 않게 됩니다. `src/commands/interactive.js`의 193~204행(질문 흐름)과 `src/ui/prompts.js`(질문 UI 컴포넌트, `pickBranch` 등이 정의된 것으로 추정됩니다)가 수정 대상이 될 것으로 보이며, `src/core/branches.js`의 `resolveBranchConfig()` 자체(모드 판정 로직)는 그대로 두고 호출하는 쪽의 입력 흐름만 바꾸면 될 것으로 추정됩니다.

### 고려한 다른 방법(선택)

두 번째 질문("개발 브랜치를 선택하세요")의 기본값이나 안내 문구만 바꿔서 "여기에 릴리스 브랜치와 같은 이름을 입력하면 trunk-based가 됩니다"라고 사전 고지하는 더 작은 수정도 가능합니다. 다만 이 경우에도 사용자가 "왜 같은 이름을 입력해야 다른 모드가 되는지" 이해하기 번거로워, 전략을 먼저 명시적으로 선택하게 하는 쪽이 더 명확해 보입니다.
